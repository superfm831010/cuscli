## 2. 项目级代码自动生成功能

### 2.1 功能描述

项目级代码自动生成功能是 Cuscli 的核心能力,基于大语言模型技术,从自然语言需求描述自动生成符合项目规范的可执行代码。不同于传统的代码补全工具,该功能能够理解整个项目的架构、技术栈和编码风格,生成具有项目级一致性的代码。

#### 2.1.1 核心能力

**🎯 项目整体理解**

- **代码库索引**: 自动扫描并索引项目中的所有代码文件
- **架构识别**: 理解项目的分层架构和模块划分
- **技术栈分析**: 自动识别使用的框架、库和工具
- **规范学习**: 从现有代码中学习编码风格和命名规范

**🎯 智能代码生成**

- **需求理解**: 从自然语言描述中提取技术需求
- **代码生成**: 生成符合项目规范的完整代码
- **依赖管理**: 自动添加必要的导入和依赖声明
- **错误处理**: 生成包含异常处理的健壮代码

**🎯 多种生成模式**

- **新建文件**: 创建全新的代码文件
- **修改现有文件**: 基于现有代码进行修改和扩展
- **批量生成**: 一次性生成多个相关文件
- **增量生成**: 逐步完善和优化代码

### 2.2 应用场景

#### 场景 1: 新功能开发

**业务需求**: 需要为海关系统添加一个新的数据导入功能。

**使用方式**:
```
用户: 请创建一个 Excel 数据导入功能,支持海关申报单数据导入
```

**系统响应**:
- 分析项目现有的导入功能实现方式
- 生成符合项目架构的导入模块代码
- 包含数据验证、错误处理、日志记录
- 自动添加单元测试代码

**预期成果**: 生成完整的数据导入模块,包括 Controller、Service、工具类和测试代码。

#### 场景 2: Bug 修复

**业务需求**: 修复数据查询中的性能问题。

**使用方式**:
```
用户: 优化 UserService.queryUsers 方法的查询性能,该方法在大数据量时很慢
```

**系统响应**:
- 分析现有代码的性能瓶颈
- 提供优化建议(如添加索引、分页查询)
- 生成优化后的代码
- 保持接口签名不变

**预期成果**: 优化后的查询方法,性能提升明显,不影响现有调用。

#### 场景 3: 代码重构

**业务需求**: 将单体代码拆分为多个模块。

**使用方式**:
```
用户: 将 UserController 中的权限验证逻辑提取为独立的 AuthService
```

**系统响应**:
- 分析现有权限验证逻辑
- 创建新的 AuthService 类
- 更新 UserController 调用新的服务
- 更新相关的测试代码

**预期成果**: 代码结构更清晰,职责划分更合理。

### 2.3 操作说明

#### 2.3.1 交互式聊天模式

**步骤 1: 启动系统**

```bash
# 在项目根目录启动
python -m autocoder.chat_auto_coder
```

**步骤 2: 描述需求**

在聊天界面输入需求描述:

```
请创建一个用户登录功能,包含:
1. 用户名密码验证
2. 登录日志记录
3. 失败次数限制
4. 符合海关开发规范
```

**步骤 3: 系统分析与生成**

系统会:
1. 分析项目现有的认证机制
2. 确定需要创建/修改的文件
3. 生成代码并显示变更内容
4. 询问是否应用变更

**步骤 4: 确认应用**

```
✅ 生成代码预览:

📄 新建文件: src/auth/LoginService.py
📄 修改文件: src/controller/AuthController.py

是否应用这些变更? (y/n)
```

输入 `y` 确认应用。

#### 2.3.2 命令行模式

**单次执行模式**:

```bash
auto-coder --query "创建用户登录功能" \
           --file actions/login_feature.yml \
           --model deepseek_chat
```

**批量执行模式**:

创建 YAML 配置文件 `actions/login_feature.yml`:

```yaml
# 登录功能开发任务
task_name: "用户登录功能开发"
requirements:
  - "实现用户名密码认证"
  - "添加登录日志"
  - "限制失败次数"
files:
  - "src/auth/"
  - "src/controller/AuthController.py"
output_format: "editblock"
```

执行:
```bash
auto-coder --file actions/login_feature.yml
```

#### 2.3.3 IDE 集成模式

在支持的 IDE (如 VS Code、PyCharm) 中:

1. 选中需要修改的代码段
2. 右键选择 "Cuscli: 重构代码"
3. 输入重构需求
4. 查看生成的代码 diff
5. 确认应用

### 2.4 配置参数

| 参数 | 说明 | 默认值 | 可选值 |
|------|------|--------|--------|
| `model` | 代码生成使用的 AI 模型 | deepseek_chat | gpt-4, claude-3, 通义千问等 |
| `code_model` | 专用代码模型(优先级更高) | 无 | 同上 |
| `output_format` | 代码输出格式 | editblock | editblock, diff, whole |
| `human_as_model` | 人工审核模式 | false | true, false |
| `auto_merge` | 自动合并代码 | true | true, false |

### 2.5 最佳实践

#### ✅ 推荐做法

1. **需求描述清晰**: 提供具体的功能要求和约束条件
2. **分步实现**: 复杂功能拆分为多个小步骤
3. **代码审查**: 生成后仔细检查代码逻辑
4. **测试验证**: 运行测试确保功能正确

#### ❌ 避免做法

1. **需求模糊**: "优化一下代码" 这样的描述过于笼统
2. **一次太多**: 一次性要求实现过多功能
3. **盲目应用**: 不检查直接应用生成的代码
4. **忽略测试**: 不运行测试就提交代码

## 3. 项目记忆与上下文感知功能

### 3.1 功能描述

项目记忆与上下文感知功能使 Cuscli 能够"记住"项目的历史信息和开发上下文,在生成代码时参考项目的架构、风格、历史决策,确保生成的代码与项目整体保持一致。

#### 3.1.1 核心能力

**🧠 项目记忆机制**

- **代码索引**: 对项目所有代码建立语义索引
- **架构记忆**: 记住项目的分层架构和模块关系
- **规范记忆**: 学习并记住项目的编码规范
- **决策记忆**: 记录重要的技术决策和原因

**🧠 上下文感知**

- **文件关联**: 理解文件之间的依赖关系
- **代码引用**: 追踪类、函数的调用关系
- **历史变更**: 了解代码的演进历史
- **会话记忆**: 在同一会话中记住之前的对话

**🧠 智能检索**

- **相似代码检索**: 查找项目中类似的实现
- **接口查找**: 快速定位接口定义和实现
- **依赖分析**: 分析代码的依赖关系
- **影响范围**: 评估代码变更的影响范围

### 3.2 应用场景

#### 场景 1: 保持代码风格一致

**业务需求**: 新增功能需要与现有代码风格保持一致。

**使用方式**:
```
用户: 创建一个新的数据导出 Service
```

**系统响应**:
- 检索项目中已有的 Service 类
- 分析现有 Service 的结构和命名规范
- 生成符合现有风格的新 Service
- 使用相同的异常处理模式

**预期成果**: 新生成的代码与项目现有代码风格完全一致,代码审查更容易通过。

#### 场景 2: 理解业务上下文

**业务需求**: 修改一个功能,需要了解相关的业务逻辑。

**使用方式**:
```
用户: 在申报单审核流程中添加风险评估环节
```

**系统响应**:

- 理解现有审核流程的步骤
- 确定风险评估的插入位置
- 生成符合现有流程的代码

**预期成果**: 新功能无缝集成到现有业务流程中。

#### 场景 3: 利用历史实现

**业务需求**: 实现一个新功能,项目中有类似的实现。

**使用方式**:
```
用户: 添加 PDF 报表导出功能

**系统响应**:
- 检索到项目中已有 Excel 导出功能

3. **利用会话记忆**: 复杂任务在同一会话中完成
4. **保存重要会话**: 保存关键的开发会话以便后续参考

#### ❌ 避免做法

1. **索引过时**: 长期不更新索引导致检索不准确
2. **忽略检索**: 不检索直接生成导致重复实现
3. **会话过长**: 单个会话包含过多不相关的内容

## 4. 多文件协同编码功能

### 4.1 功能描述

多文件协同编码功能允许 Cuscli 在一次操作中同时修改多个相关联的代码文件,自动维护文件间的依赖关系和接口一致性,实现真正的项目级代码编辑。

#### 4.1.1 核心能力

**📁 文件关联分析**

- **依赖识别**: 自动识别文件之间的依赖关系
- **调用分析**: 追踪函数和类的调用链
- **接口匹配**: 确保接口定义和实现一致
- **影响评估**: 评估变更对其他文件的影响

**📁 批量修改**

- **同步修改**: 同时修改多个文件保持一致性
- **级联更新**: 修改接口时自动更新所有调用处
- **重构支持**: 支持跨文件的代码重构
- **测试更新**: 代码修改后自动更新相关测试

**📁 冲突处理**

- **冲突检测**: 检测文件间的潜在冲突
- **智能合并**: 自动合并兼容的修改
- **冲突提示**: 无法自动合并时提示用户
- **版本回滚**: 支持撤销整批修改

## 8. AI 代码审核功能

### 8.1 功能描述

    "token": "glpat-xxx...",
    "username": "your-username",
    "default_project": "your-project-id",
    "timeout": 30,
    "retry": 3
  },
  "default_platform": "github"

```

### 9.5 最佳实践

#### ✅ 推荐做法

1. **及时创建 PR**: 功能完成后及时创建 PR,不要积累
2. **清晰描述**: PR 标题和描述清晰准确
3. **关联 Issue**: PR 与 Issue 关联,方便追溯
4. **小而聚焦**: 每个 PR 只包含一个功能或修复
5. **响应审查**: 及时响应审查意见并修改

#### ❌ 避免做法

1. **巨型 PR**: 一个 PR 包含大量变更
2. **描述不清**: PR 描述过于简单或没有描述
3. **忽略 CI**: CI 失败不处理就请求合并
4. **强制合并**: 未经审查就强制合并代码

### 10.3 使用建议

#### 日常开发推荐流程

1. **项目初始化**:
   ```bash
   /index_build              # 构建代码索引
   /conf                     # 配置 AI 模型
   ```

2. **功能开发**:
   ```bash
   描述需求 -> AI 生成代码 -> 检查代码 -> 运行测试 -> 提交代码
   ```

3. **代码提交**:
   ```bash
   /check /git /diff         # 提交前检查
   /commit                   # 智能提交
   /git /pr /create          # 创建 PR
   ```

4. **代码审查**:
   ```bash
   /git /pr /list            # 查看 PR 列表
   /git /ci /status          # 检查 CI 状态
   ```
