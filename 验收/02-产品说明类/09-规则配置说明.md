## 1. 规则体系概述

### 1.1 规则体系简介

Cuscli AI 编程助手平台内置了完善的代码检查规则体系，帮助开发团队确保代码质量符合海关软件开发规范。规则体系基于AI大语言模型（LLM）进行智能检查，能够理解代码语义和上下文，提供更准确的问题识别和修改建议。

**规则体系特点**：
- **全面覆盖**：包含前端105条、后端63条，共168条规则
- **智能检查**：基于LLM语义理解，不仅检查语法，更关注代码质量和规范
- **海关定制**：针对海关软件开发规范进行深度定制
- **灵活配置**：支持启用/禁用、自定义规则、规则优先级设置
- **分类清晰**：按功能分类，便于管理和使用

### 1.3 规则检查流程

```
代码检查流程：

用户发起检查
    ↓
加载规则配置（rules_config.json）
    ↓
根据配置加载规则文件
├── backend_rules.md（后端规则）
└── frontend_rules.md（前端规则）
    ↓
扫描目标文件和文件夹
    ↓
根据文件类型匹配适用规则
├── *.py, *.java → 后端规则
└── *.js, *.ts, *.vue → 前端规则
    ↓
过滤已禁用的规则
    ↓
对每个文件应用规则集
├── 大文件自动分块（>5000行）
├── 并发检查（3-5个文件同时）
└── 调用LLM进行语义分析
    ↓
收集检查结果
├── 按严重程度分类
├── 按规则类别分组
└── 统计问题数量
    ↓
生成检查报告
├── JSON格式（机器可读）
└── Markdown格式（人工可读）
    ↓
展示并保存报告
```

## 2. 规则文件结构

### 2.1 规则文件组织

Cuscli 的规则文件存储在 `rules/` 目录下：

```
rules/
├── rules_config.json          # 规则配置文件（主配置）
├── backend_rules.md           # 后端规则文件（63条）
└── frontend_rules.md          # 前端规则文件（105条）
```

### 2.2 规则定义格式

每条规则采用Markdown格式定义，包含以下标准字段：

#### 2.2.1 规则字段说明

```markdown
### 规则ID: [规则唯一标识]
**标题**: [规则简短标题]
**严重程度**: [error|warning|info]
**描述**: [规则详细描述]

**说明**: [规则说明和背景]

**错误示例**（可选）:
```[代码语言]
[错误代码示例]
```

**正确示例**（可选）:
```[代码语言]
[正确代码示例]
```

---
```

**字段详解**：

| 字段 | 必填 | 说明 | 示例 |
|------|------|------|------|
| 规则ID | ✅ | 唯一标识，格式：`[类型]_[编号]` | `backend_001`、`frontend_001` |
| 标题 | ✅ | 规则简短标题，10字以内 | "项目父依赖规范" |
| 严重程度 | ✅ | error/warning/info 三选一 | `error` |
| 描述 | ✅ | 规则详细描述，说明具体要求 | "项目父依赖应为cacp-spring-boot-parent" |
| 说明 | ✅ | 规则背景和原因说明 | "确保项目继承正确的父级依赖..." |
| 错误示例 | ⭕ | 不符合规则的代码示例 | 见下文示例 |
| 正确示例 | ⭕ | 符合规则的代码示例 | 见下文示例 |

#### 2.2.2 完整规则示例

**后端规则示例**：
```markdown
### 规则ID: backend_006
**标题**: 避免复杂的嵌套结构
**严重程度**: warning
**描述**: 代码中不应存在复杂的if-else和for循环嵌套（嵌套层数大于3、语句块逻辑除注释外大于20行）

**说明**: 复杂的嵌套结构会降低代码可读性和可维护性，应考虑重构为更清晰的结构。

**错误示例**:
```java
if (condition1) {
    for (int i = 0; i < n; i++) {
        if (condition2) {
            for (int j = 0; j < m; j++) {
                if (condition3) {
                    // 嵌套层数过深
                }
            }
        }
    }
}
```

**正确示例**:
```java
// 抽取内层逻辑为独立方法
if (condition1) {
    processOuterCondition();
}

private void processOuterCondition() {
    for (int i = 0; i < n; i++) {
        processItem(i);
    }
}
```

---
```

**前端规则示例**：
```markdown
### 规则ID: frontend_006
**标题**: 禁止三元运算符嵌套
**严重程度**: warning
**描述**: 禁止使用三个及以上三元运算符嵌套使用

**说明**: 嵌套的三元运算符难以理解和维护。

**错误示例**:
```javascript
const value = a ? b : c ? d : e ? f : g; // 难以阅读
```

**正确示例**:
```javascript
// 使用if-else或switch
let value;
if (a) {
    value = b;
} else if (c) {
    value = d;
} else if (e) {
    value = f;
} else {
    value = g;
}
```

---
```

### 2.3 规则编号规范

**类型前缀**：

### 3.1 后端规则（63条）

#### 3.1.1 应用开发架构使用（5条）

**规则概述**：确保后端项目符合海关应用开发架构规范，包括依赖管理、目录结构、命名规范等。

**核心规则**：

| 规则ID | 标题 | 严重程度 | 核心要求 |
|--------|------|---------|---------|
| backend_001 | 项目父依赖规范 | error | 继承 cacp-spring-boot-parent |
| backend_002 | 项目核心依赖规范 | error | 使用 cacp-service 或 cacp-job starter |
| backend_003 | 数据源依赖规范 | error | 使用 cacp-datasource starter |
| backend_004 | 项目目录结构规范 | warning | 遵循标准目录结构（config、service、dao等） |

**应用场景**：

- 项目重构时验证
- 项目交付前审查

#### 3.1.2 代码结构（10条）

**规则概述**：控制代码复杂度，确保代码结构清晰、易于理解和维护。

**核心规则**：

| 规则ID | 标题 | 严重程度 | 核心要求 |
|--------|------|---------|---------|
| backend_006 | 避免复杂的嵌套结构 | warning | 嵌套层数≤3，代码块≤20行 |
| backend_007 | 判断逻辑简洁清晰 | warning | 逻辑运算符≤3个 |
| backend_008 | 合理使用函数 | warning | 函数行数≤50行，参数≤5个 |
| backend_009 | 避免重复代码 | warning | 相同代码块应抽取为方法 |
| backend_010 | 类职责单一 | warning | 一个类只负责一项功能 |

**典型问题**：
- 嵌套层数过深（>3层）
- 函数过长（>50行）
- 参数过多（>5个）
- 重复代码未抽取
- 类职责不单一

#### 3.1.3 异常处理（8条）

**规则概述**：规范异常处理机制，确保系统健壮性。

**核心规则**：

| 规则ID | 标题 | 严重程度 | 核心要求 |
|--------|------|---------|---------|
| backend_015 | 必须处理异常 | error | 不能捕获后不处理或只打印日志 |
| backend_016 | 异常信息完整 | warning | 异常信息应包含上下文 |
| backend_017 | 异常类型准确 | warning | 抛出准确的异常类型 |
| backend_018 | 避免捕获通用异常 | warning | 不直接捕获 Exception |
| backend_019 | 资源必须释放 | error | finally块中释放资源 |

**典型问题**：
```java
// ❌ 错误：捕获后不处理
try {
    riskyOperation();
} catch (Exception e) {
    // 空catch块
}

// ✅ 正确：记录日志并处理
try {
    riskyOperation();
} catch (BusinessException e) {
    logger.error("操作失败: {}", e.getMessage(), e);
    throw new ServiceException("业务处理失败", e);
}
```

#### 3.1.4 安全性（12条）

**规则概述**：防止常见安全漏洞，保护系统和数据安全。

**核心规则**：

| 规则ID | 标题 | 严重程度 | 核心要求 |
|--------|------|---------|---------|
| backend_025 | SQL注入防护 | error | 使用参数化查询，禁止字符串拼接SQL |
| backend_026 | XSS攻击防护 | error | 输出前进行HTML转义 |
| backend_027 | CSRF防护 | error | 使用CSRF Token |
| backend_028 | 敏感信息保护 | error | 密码、密钥加密存储，不记录日志 |
| backend_029 | 文件上传安全 | error | 验证文件类型、大小，防止路径遍历 |

**安全问题示例**：

**SQL注入**：
```java
// ❌ 错误：字符串拼接SQL
String sql = "SELECT * FROM users WHERE username = '" + username + "'";

// ✅ 正确：参数化查询
String sql = "SELECT * FROM users WHERE username = ?";
PreparedStatement stmt = conn.prepareStatement(sql);
stmt.setString(1, username);
```

**敏感信息保护**：
```java
// ❌ 错误：明文存储密码
user.setPassword(password);

// ✅ 正确：加密存储
user.setPassword(passwordEncoder.encode(password));
```

### 3.2 前端规则（105条）

#### 3.2.1 应用开发架构使用（4条）

**规则概述**：确保前端项目符合海关"大中台+微应用"架构。

**核心规则**：

| 规则ID | 标题 | 严重程度 | 核心要求 |

| frontend_001 | 统一入口集成 | error | 必须集成到统一入口平台 |
| frontend_002 | 技术栈规范 | error | 使用Vue、Vite、TypeScript、ElementPlus |

### 4.2 配置项详解

#### 4.2.1 rule_sets（规则集配置）

**作用**：定义不同语言/技术栈的规则集。

**后端规则集配置**：
```json
{

      "description": "Python/Java 后端代码检查规则，共63条",
      "categories": [                     // 规则分类
        "应用开发架构使用",
        "代码结构",

        "安全性",
        "其他",
        "日志输出",
        "接口定义",
        "数据库",

**配置项说明**：

| 配置项 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| enabled | boolean | ✅ | 是否启用该规则集 |
| file_patterns | array | ✅ | 匹配的文件模式（glob格式） |
| severity_threshold | string | ⭕ | 最低严重程度（info/warning/error） |
| disabled_rules | array | ⭕ | 禁用的规则ID列表 |
| description | string | ⭕ | 规则集描述 |
| categories | array | ⭕ | 规则分类列表 |

#### 4.2.2 global_settings（全局设置）

**作用**：控制检查行为的全局参数。

```json
{
  "global_settings": {
    "max_workers": 5,                   // 最大并发检查数
    "chunk_size": 4000,                 // 大文件分块大小（行数）
    "chunk_overlap": 200,               // 分块重叠行数
    "ignored_patterns": [               // 忽略的文件/目录
      "__pycache__",
      "*.pyc",
      "node_modules",
      "dist",
      "build",
      ".git",
      ".venv",
      "venv",
      "*.min.js",
      "*.min.css"
    ],
    "report_directory": "codecheck",    // 报告保存目录
    "enable_progress_tracking": true,   // 启用进度跟踪
    "enable_resume": true               // 启用中断恢复
  }
}
```

**配置项说明**：

| 配置项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| max_workers | integer | 5 | 并发检查文件数（1-10） |
| chunk_size | integer | 4000 | 大文件分块大小（行） |
| chunk_overlap | integer | 200 | 分块重叠行数，避免上下文断裂 |
| ignored_patterns | array | - | 忽略的文件模式列表 |
| report_directory | string | "codecheck" | 报告保存目录（相对于项目根目录） |
| enable_progress_tracking | boolean | true | 是否保存检查进度 |
| enable_resume | boolean | true | 是否支持中断后恢复 |

**性能调优建议**：
- **max_workers**：根据CPU核心数和LLM API限流调整，一般设置为 3-5
- **chunk_size**：大文件分块大小，4000行是经验值，可根据实际情况调整
- **chunk_overlap**：重叠行数确保上下文完整，不建议小于100行

#### 4.2.3 severity_levels（严重程度定义）

**作用**：定义不同严重程度的含义和优先级。

    }
  }
}
```

**严重程度**: error

// ❌ 错误：使用字符串
if (order.getStatus().equals("PENDING")) {

if (order.getStatusCode() == 1) {
    // ...
}

```java
// ✅ 正确：使用枚举
if (order.getStatus() == OrderStatus.PENDING) {
    // ...
}
```

### 10.2 常见问题

#### 10.2.1 规则相关

**Q1: 如何快速了解所有规则？**
A: 可以查看 `rules/backend_rules.md` 和 `rules/frontend_rules.md` 文件，或参考本文档第3章"内置规则详解"。

**Q2: 某条规则不适合我的项目，如何禁用？**
A: 在 `rules/rules_config.json` 的 `disabled_rules` 数组中添加该规则ID。

**Q3: 规则检查结果是否100%准确？**
A: 基于LLM的检查具有很高的准确率（85%+），但可能存在误报或漏报。建议结合人工审查。

#### 10.2.2 配置相关

**Q4: 如何修改并发检查数量？**
A: 修改 `rules/rules_config.json` 中的 `global_settings.max_workers` 参数。

**Q5: 大文件检查很慢，如何优化？**
A: 可以调整 `chunk_size` 参数，或者在 `.autocoderignore` 中排除不需要检查的大文件。

**Q6: 如何只检查变更的文件？**
A: 使用 `/check /file` 命令指定具体文件，或者通过Git获取变更文件列表后批量检查。

#### 10.2.3 使用相关

**Q7: 检查报告保存在哪里？**
A: 默认保存在 `.auto-coder/codecheck/reports/` 目录，可通过配置文件修改。

**Q8: 如何在CI/CD中集成代码检查？**
A: 参考本文档第8.3.1节"质量门禁"部分的CI/CD配置示例。

**Q9: 检查过程中断了，如何恢复？**
A: 如果启用了 `enable_resume` 配置，可以使用 `/check /resume` 命令继续检查。
