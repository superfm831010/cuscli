## 1. AI模型概述

### 1.1 AI模型在Cuscli中的作用

Cuscli AI 编程助手平台的核心能力来自于大语言模型（LLM）。AI模型在系统中承担以下关键任务：

**核心功能**：
1. **代码生成**：根据需求描述自动生成代码
2. **代码理解**：分析和理解现有代码结构
3. **代码检查**：基于规则进行智能代码质量检查
4. **智能对话**：与用户进行自然语言交互
5. **代码优化**：提供代码改进建议
6. **文档生成**：自动生成代码文档和注释
7. **问题诊断**：分析代码问题并给出解决方案

### 1.2 模型类型与用途

Cuscli 支持配置多个不同用途的AI模型，每种模型针对特定任务进行优化：

| 模型类型 | 用途说明 | 推荐场景 |
|---------|---------|---------|
| **model** | 主模型，处理通用任务 | 综合性任务、默认选择 |
| **code_model** | 代码生成专用模型 | 代码编写、重构、优化 |
| **chat_model** | 对话交互模型 | 用户问答、需求澄清 |
| **index_model** | 代码索引构建模型 | 项目分析、代码理解 |
| **emb_model** | 文本嵌入模型 | 向量化、语义检索 |
| **vl_model** | 视觉语言模型 | 图片理解、UI分析 |
| **planner_model** | 任务规划模型 | 复杂任务分解 |
| **designer_model** | 系统设计模型 | 架构设计、接口设计 |
| **commit_model** | 提交信息生成模型 | Git提交信息生成 |

### 1.3 模型产品模式

Cuscli 支持两种产品模式，适应不同的部署需求：

#### 1.3.1 Lite模式（推荐）

**特点**：
- 使用 SimpleByzerLLM 框架
- 直接调用模型API，无需额外服务
- 配置简单，易于部署
- 适合单机和小团队使用

**适用场景**：
- 个人开发者
- 小型团队（<10人）
- 快速试用和测试
- 内网环境（配置本地模型）

#### 1.3.2 Pro模式

**特点**：
- 使用 ByzerLLM + Ray 分布式框架
- 支持集群部署和负载均衡
- 高性能、高并发
- 支持私有化模型部署

**适用场景**：
- 大型团队（>10人）
- 高并发需求
- 私有化模型部署
- 对性能有较高要求

**本项目采用**：Lite模式（SimpleByzerLLM）

## 4. 模型配置方法

### 4.1 配置文件结构

Cuscli 的模型配置通过YAML文件进行管理，支持多种配置方式。

**配置文件位置**：
- 项目配置：`.auto-coder/project.yaml`
- Action配置：`actions/[任务名].yaml`
- 命令行参数：`--model` 等参数

### 4.2 基本配置

#### 4.2.1 单模型配置

**配置示例**：
```yaml
# .auto-coder/project.yaml

# 使用OpenAI GPT-4o
model: gpt-4o
model_max_length: 128000
model_max_input_length: 100000

# API配置
api_key: ENV {{OPENAI_API_KEY}}
api_base: https://api.openai.com/v1
```

**配置说明**：
- `model`：模型名称
- `model_max_length`：模型最大上下文长度
- `model_max_input_length`：单次请求最大输入长度
- `api_key`：API密钥（使用环境变量）
- `api_base`：API基础地址

#### 4.2.2 环境变量配置

**设置环境变量**（推荐方式）：

**Linux/Mac**：
```bash
# 在 ~/.bashrc 或 ~/.zshrc 中添加
export OPENAI_API_KEY="sk-xxx"
export ANTHROPIC_API_KEY="sk-ant-xxx"
export ZHIPU_API_KEY="xxx"
```

**Windows**：
```powershell
# PowerShell
$env:OPENAI_API_KEY="sk-xxx"

# 或在系统环境变量中设置（永久）
```

**在配置文件中引用**：
```yaml
api_key: ENV {{OPENAI_API_KEY}}
```

### 4.3 多模型配置

#### 4.3.1 不同任务使用不同模型

```yaml
# .auto-coder/project.yaml

# 主模型（通用任务）
model: gpt-4o
api_key: ENV {{OPENAI_API_KEY}}

# 代码生成专用模型
code_model: claude-3-5-sonnet-20241022
code_model_api_key: ENV {{ANTHROPIC_API_KEY}}
code_model_api_base: https://api.anthropic.com

# 对话模型（成本优先）
chat_model: gpt-3.5-turbo
chat_model_api_key: ENV {{OPENAI_API_KEY}}

# 索引构建模型
index_model: gpt-4o
index_model_api_key: ENV {{OPENAI_API_KEY}}

# 嵌入模型
emb_model: text-embedding-3-small
emb_model_api_key: ENV {{OPENAI_API_KEY}}
```

#### 4.3.2 备选模型配置

支持多个模型用逗号分隔，系统会依次尝试：

```yaml
# 代码生成：优先Claude，失败则用GPT-4o，再失败用DeepSeek
code_model: claude-3-5-sonnet,gpt-4o,deepseek-coder
```

**使用场景**：
- 主模型限流或不可用时自动切换
- 降低单一模型依赖风险
- 成本控制（优先使用便宜模型）

## 5. 多模型协同配置

### 5.1 协同策略

#### 5.1.1 任务分工策略

根据任务特点分配不同模型：

```yaml
# 高质量代码生成：Claude
code_model: claude-3-5-sonnet

# 快速对话：GPT-3.5
chat_model: gpt-3.5-turbo

# 提交信息生成：低成本模型
commit_model: glm-4-flash

# 代码检查：高质量模型
model: gpt-4o
```

**优势**：
- 质量与成本平衡
- 各模型发挥所长
- 降低整体成本

#### 5.1.2 备选容错策略

```yaml
# 主模型+备选模型
code_model: claude-3-5-sonnet,gpt-4o,deepseek-coder
```

**工作机制**：
1. 优先使用 Claude 3.5 Sonnet
2. 如果失败（限流、超时、错误），自动切换到 GPT-4o
3. 如果再失败，切换到 DeepSeek Coder

**优势**：
- 提高可用性
- 降低服务中断风险
- 自动容错

#### 5.1.3 成本优化策略


## 8. 常见问题解答

### 8.1 配置相关

**Q1: 如何知道我配置的模型是否生效？**

A: 在 `chat-auto-coder` 中输入 `/conf` 命令查看当前配置：
```bash
/conf

# 输出示例：
Current Configuration:
- model: gpt-4o
- code_model: claude-3-5-sonnet
- chat_model: gpt-3.5-turbo
```

**Q2: 环境变量配置后不生效怎么办？**

A:
1. 确认环境变量已设置：`echo $OPENAI_API_KEY`
2. 重新启动终端或source配置文件：`source ~/.bashrc`
3. 确认配置文件中正确引用：`api_key: ENV {{OPENAI_API_KEY}}`

**Q3: 可以同时使用多个不同厂商的模型吗？**

A: 可以！示例：
```yaml
model: gpt-4o                    # OpenAI
code_model: claude-3-5-sonnet    # Anthropic
chat_model: glm-4                # 智谱AI
```

### 8.2 模型使用

**Q4: 如何选择合适的模型？**

A: 参考本文档第3章"模型选择建议"，主要考虑：
- 任务复杂度
- 质量要求
- 成本预算
- 响应速度需求

**Q5: 模型响应很慢怎么办？**

A:
1. 更换响应更快的模型（如GPT-3.5 Turbo、GLM-4-Flash）
2. 减少上下文长度
3. 检查网络连接
4. 使用代理加速

**Q6: 模型返回的代码质量不高怎么办？**

A:
1. 更换更强大的模型（如Claude 3.5 Sonnet）
2. 提供更详细的需求描述
3. 增加相关上下文信息
4. 使用示例代码引导

### 8.3 错误处理

**Q7: 出现"API key无效"错误怎么办？**

A:
1. 检查API key是否正确
2. 确认API key未过期
3. 检查账户余额
4. 确认环境变量设置正确

**Q8: 出现"Rate limit exceeded"错误怎么办？**

A:
1. 等待一段时间后重试
2. 升级API账户等级
3. 配置备选模型：`code_model: gpt-4o,claude-3-5-sonnet`
4. 降低并发请求数

**Q9: 出现"Context length exceeded"错误怎么办？**

A:
1. 减少输入的代码量
2. 使用 `.autocoderignore` 排除无关文件
3. 设置 `model_max_input_length` 限制
4. 更换支持更长上下文的模型（如Claude 200K）

### 8.4 成本相关

**Q10: 如何降低使用成本？**

A:
1. 使用国产模型（DeepSeek、GLM、Qwen）
2. 简单任务使用便宜模型
3. 启用缓存避免重复请求
4. 使用本地模型（完全免费）

**Q11: 本地模型效果如何？**

A:
- 小模型（7B）：适合简单代码生成、对话
- 中等模型（14B/33B）：可满足大部分需求
- 大模型（70B+）：接近GPT-4质量，但需要高性能硬件

**Q12: 内网环境如何使用？**

A:
1. 部署本地模型（Ollama、vLLM）
2. 使用内网AI平台API
3. 离线模型推理
