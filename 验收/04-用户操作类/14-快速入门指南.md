## 1. 欢迎使用 Cuscli AI编程助手

### 1.1 Cuscli 是什么？

Cuscli AI编程助手是一款**智能化的编程辅助工具**，它能够：

✅ **自动生成代码** - 根据您的需求描述，自动生成高质量的代码
✅ **智能检查代码** - 自动检查代码质量，发现潜在问题
✅ **理解代码逻辑** - 帮助您理解复杂的代码实现
✅ **重构优化代码** - 提供代码优化建议和自动重构
✅ **集成工作流程** - 与Git、IDE无缝集成

### 1.2 为什么选择 Cuscli？

| 传统开发方式 | 使用 Cuscli |
|------------|------------|
| ⏰ 编写重复代码耗时长 | ⚡ 自动生成，节省80%时间 |
| 🐛 手工检查容易遗漏 | 🔍 AI智能检查，零遗漏 |
| 📚 查阅文档理解代码 | 💬 对话即懂，即问即答 |
| 🔧 手工重构风险大 | 🛡️ 智能重构，安全可靠 |

### 1.3 快速导航

- **新手用户**：建议按顺序阅读本指南（约5分钟）
- **有经验用户**：直接跳到 [第3章 典型使用场景](#3-典型使用场景)

## 2. 5分钟快速体验

### 2.1 启动 Cuscli

#### 方式一：命令行启动（推荐）

打开终端，进入您的项目目录：

```bash
# Linux / macOS
cd /path/to/your/project
auto-coder.chat

# Windows
cd C:\path\to\your\project
auto-coder.chat
```

**看到以下界面表示启动成功**：

```
╔════════════════════════════════════════════════════════════╗
║        Cuscli AI编程助手 v1.1.0                            ║
║        基于 auto-coder v1.0.39                             ║
╚════════════════════════════════════════════════════════════╝

AI模型: gpt-4o (已连接)
工作目录: /path/to/your/project
Git状态: main分支, 干净

请输入您的需求 (输入 /help 查看帮助):
>
```

#### 方式二：指定配置文件启动

如果您有自定义配置：

```bash
auto-coder.chat --config /path/to/your/config.yml
```

### 2.2 第一次对话：生成代码

让我们尝试生成一个简单的Python函数：

```
> 请帮我写一个Python函数，计算两个数的最大公约数
```

**Cuscli 会回复**：

```python
✓ 代码已生成并保存到：math_utils.py

def gcd(a, b):
    """
    计算两个数的最大公约数

    参数:
        a (int): 第一个整数
        b (int): 第二个整数

    返回:
        int: 最大公约数

    示例:
        >>> gcd(48, 18)
        6
    """
    while b:
        a, b = b, a % b
    return a

✓ 建议：已自动生成单元测试到 tests/test_math_utils.py
```

**就是这么简单！** 代码已经自动生成并保存到文件中。

### 2.3 第二次对话：检查代码

现在让我们检查刚才生成的代码：

```
> /check /file math_utils.py
```

**Cuscli 会分析代码并给出报告**：

```
正在检查文件: math_utils.py
✓ 代码规范检查通过
✓ 类型检查通过
✓ 安全检查通过
! 发现1个建议优化项:

建议1：添加参数类型检查
  位置：math_utils.py:12
  说明：建议在函数开始时检查参数类型，避免传入非整数参数
  建议代码：
    if not isinstance(a, int) or not isinstance(b, int):
        raise TypeError("参数必须是整数")

✓ 检查报告已保存到：.auto-coder/reports/check_math_utils_20251101.md
```

### 2.4 第三次对话：修改代码

根据检查建议，让我们优化代码：

```
> 请根据检查建议，添加参数类型检查
```

**Cuscli 会自动修改代码**：

```
✓ 代码已更新：math_utils.py

已添加以下改进：
1. 添加参数类型检查
2. 添加参数值范围检查（避免负数）
3. 更新了单元测试

✓ 所有测试通过 (3 passed)
```

**恭喜！** 您已经完成了第一次完整的AI辅助编程体验。

### 3.2 场景二：智能代码检查

#### 使用时机
- 代码编写完成后
- 提交Git之前
- 代码审查时

#### 操作步骤

**步骤1：检查单个文件**
```
> /check /file src/user_service.py
```

**步骤2：检查整个目录**
```
> /check /folder src/
```

**步骤3：查看详细报告**

检查报告会自动保存到 `.auto-coder/reports/` 目录，包含：
- ✅ 通过项：代码规范、类型检查、安全检查
- ⚠️ 警告项：代码异味、潜在问题
- ❌ 错误项：严重问题、必须修复

**步骤4：根据报告修复问题**
```
> 请修复检查报告中的所有错误项
```

#### 检查内容说明

| 检查类型 | 检查内容 | 重要性 |
|---------|---------|-------|
| 🔍 代码规范 | 命名规范、代码格式、注释完整性 | 中 |
| 🛡️ 安全检查 | SQL注入、XSS、硬编码密码 | 高 |
| 📊 类型检查 | 类型错误、空指针风险 | 高 |
| ⚡ 性能检查 | 性能瓶颈、资源泄漏 | 中 |
| 🎯 逻辑检查 | 死代码、逻辑错误 | 高 |
| 📚 海关规范 | 符合海关开发规范 | 高 |

#### 实用技巧

✨ **技巧1：中断后继续检查**
```
> /check /resume
```
如果检查过程被中断，可以从上次中断位置继续。

✨ **技巧2：导出检查报告**
```
> /check /report json
```
导出JSON格式报告，方便集成到CI/CD流程。

✨ **技巧3：自定义检查规则**
```
> 使用自定义规则文件：rules/custom_rules.json 进行检查
```

## 5. 快速排错

### 5.1 常见问题

#### 问题1：启动失败 - "找不到命令"

**症状**：
```bash
$ auto-coder.chat
bash: auto-coder.chat: command not found
```

**解决方案**：

✅ **方法1：检查安装**
```bash
pip show auto-coder
# 如果未安装，执行：
pip install auto-coder-1.0.39-py3-none-any.whl
```

✅ **方法2：使用完整路径**
```bash
python -m autocoder.chat_auto_coder
```

✅ **方法3：检查环境变量**
```bash
# Linux/macOS
export PATH="$HOME/.local/bin:$PATH"

# Windows
# 将 Python Scripts 目录添加到系统PATH
```

#### 问题2：AI模型连接失败

**症状**：
```
错误: 无法连接到AI模型
Connection refused: api.openai.com
```

**解决方案**：

✅ **方法1：检查网络连接**
```bash
# 测试API可访问性
curl -I https://api.openai.com

# 如果在内网环境，配置代理：
export http_proxy=http://proxy.company.com:8080
export https_proxy=http://proxy.company.com:8080
```

✅ **方法2：检查API密钥**
```bash
# 查看配置文件
cat ~/.auto-coder/config.yml

# 确认以下配置正确：
model: gpt-4o
api_key: sk-...
api_base: https://api.openai.com/v1  # 或内网API地址
```

✅ **方法3：切换到本地模型**
```yaml
# 修改配置文件使用内网部署的模型
model: http://internal-ai.company.com/v1/chat/completions
model_type: openai_compatible
```

#### 问题3：代码生成没有反应

**症状**：
```
> 请生成一个函数
(等待很久没有响应)
```

**解决方案**：

✅ **方法1：检查底部状态栏**
```
查看底部状态栏显示：
- "⏳ 正在处理..." - 正常，请等待
- "❌ 模型无响应" - 模型连接问题
- "⚠️ Token超限" - 对话历史太长
```

✅ **方法2：清空对话历史**
```
> /clear
```

✅ **方法3：增加超时时间**
```yaml
# 修改 ~/.auto-coder/config.yml
request_timeout: 180  # 增加到180秒
```

#### 问题4：文件权限错误

**症状**：
```
错误: Permission denied: /path/to/file.py
```

**解决方案**：

✅ **Linux/macOS**：
```bash
# 检查文件权限
ls -la /path/to/file.py

# 修改权限
chmod 644 /path/to/file.py
```

✅ **Windows**：
```powershell
# 右键文件 → 属性 → 安全 → 编辑
# 添加当前用户的完全控制权限
```

#### 问题5：检查报告生成失败

**症状**：
```
错误: 无法生成检查报告
OSError: [Errno 28] No space left on device
```

**解决方案**：

✅ **清理缓存空间**：
```bash
# 清理检查缓存
rm -rf .auto-coder/codecheck/cache/*

# 清理旧报告
find .auto-coder/reports/ -mtime +30 -delete
```

✅ **指定报告目录**：
```
> /check /file src/main.py --output-dir /path/with/more/space
```

## 附录A：配置文件示例

### A.1 基础配置

**文件路径**：`~/.auto-coder/config.yml`

```yaml
# AI模型配置
model: gpt-4o
api_key: ENV {{OPENAI_API_KEY}}
api_base: https://api.openai.com/v1

# 工作目录
working_dir: /path/to/your/project

# 检查规则
rules_dir: ~/.auto-coder/rules

# 代码生成设置
code_generation:
  auto_test: true        # 自动生成测试
  auto_commit: false     # 自动提交Git
  language: zh-CN        # 注释语言

# 代码检查设置
code_check:
  max_file_size: 10485760  # 10MB
  chunk_size: 5000
  parallel: 4
  report_format: markdown

# 日志设置
log_level: INFO
log_file: ~/.auto-coder/logs/auto-coder.log
```

### A.2 内网环境配置

```yaml
# 使用内网AI模型
model: http://ai-service.internal.com/v1/chat/completions
model_type: openai_compatible
api_key: internal-api-key

# 配置代理
http_proxy: http://proxy.company.com:8080
https_proxy: http://proxy.company.com:8080
no_proxy: localhost,127.0.0.1,.company.com

# 使用内网Git
git:
  platform: gitlab
  url: https://gitlab.company.com
  token: ENV {{GITLAB_TOKEN}}
```

### B.1 命令行快捷键

| 快捷键 | 功能 | 说明 |
|--------|------|------|
| `Ctrl+C` | 中断 | 中断当前操作 |
| `Ctrl+D` | 退出 | 退出Cuscli |
| `Ctrl+L` | 清屏 | 清空终端屏幕 |
| `Ctrl+A` | 行首 | 光标移到行首 |
| `Ctrl+E` | 行尾 | 光标移到行尾 |
| `Ctrl+U` | 删除行 | 删除光标前内容 |
| `Ctrl+K` | 删除到行尾 | 删除光标后内容 |
| `↑` | 上一条命令 | 浏览历史命令 |
| `↓` | 下一条命令 | 浏览历史命令 |
| `Tab` | 自动补全 | 命令/路径补全 |

### B.2 编辑快捷键（Vim模式）

如果启用了Vim模式（`/config --vim-mode`），支持以下快捷键：

| 模式 | 快捷键 | 功能 |
|------|--------|------|
| 正常 | `i` | 进入插入模式 |
| 正常 | `v` | 进入可视模式 |
| 正常 | `dd` | 删除当前行 |
| 正常 | `yy` | 复制当前行 |
| 正常 | `p` | 粘贴 |
| 插入 | `Esc` | 返回正常模式 |
