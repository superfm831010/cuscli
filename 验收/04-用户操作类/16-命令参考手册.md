## 第1章 命令概述

### 1.1 命令格式说明

Cuscli支持两种命令格式：

#### 1.1.1 自然语言命令

直接用自然语言描述需求，无需特定格式：

```
> 请帮我创建一个用户登录功能
> 优化这个函数的性能
> 解释一下这段代码的作用
```

#### 1.1.2 斜杠命令

以斜杠（`/`）开头的结构化命令：

```
/command [/subcommand] [arguments] [options]
```

**格式说明**：
- `command` - 主命令（必需）
- `subcommand` - 子命令（可选）
- `arguments` - 位置参数（可选）
- `options` - 选项参数，以`--`开头（可选）

**示例**：
```
/check /file src/main.py --verbose
│      │     │            │
│      │     │            └─ 选项
│      │     └──────────────── 参数
│      └────────────────────── 子命令
└───────────────────────────── 主命令
```

### 1.2 命令分类索引

| 类别 | 主要命令 | 页码 |
|------|---------|------|
| 基础命令 | /help, /exit, /clear | 第2章 |
| 代码生成 | /generate, /template | 第3章 |
| 代码检查 | /check | 第4章 |
| Git集成 | /git | 第5章 |
| 配置管理 | /config, /model, /rules | 第6章 |
| 项目管理 | /project, /file | 第7章 |
| 报告管理 | /report | 第8章 |
| 历史记录 | /history, /save | 第9章 |
| 工具命令 | /test, /run | 第10章 |

### 1.3 命令约定

#### 参数表示法

本手册使用以下约定表示参数：

| 符号 | 含义 | 示例 |
|------|------|------|
| `<param>` | 必需参数 | `<file_path>` |
| `[param]` | 可选参数 | `[options]` |
| `param1\|param2` | 二选一 | `merge\|rebase` |
| `...` | 可重复 | `<files>...` |

#### 选项表示法

| 格式 | 说明 | 示例 |
|------|------|------|
| `--option` | 长选项 | `--verbose` |
| `-o` | 短选项 | `-v` |
| `--option=value` | 带值选项 | `--format=json` |
| `--option value` | 带值选项（空格分隔） | `--output report.md` |

## 第2章 基础命令

### 2.1 /help - 帮助命令

**功能**：显示命令帮助信息

**语法**：
```
/help [command]
```

**参数**：
- `command` - 要查看帮助的命令名（可选）

**使用示例**：

**示例1：查看总体帮助**
```
> /help

Cuscli AI编程助手 - 命令帮助
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

基础命令：
  /help           - 显示帮助信息
  /exit           - 退出程序
  /clear          - 清空对话历史

代码生成：
  自然语言        - 直接描述需求生成代码
  /generate       - 显式生成代码

代码检查：
  /check /file    - 检查单个文件
  /check /folder  - 检查目录

更多命令请查看: /help <command>
```

**示例2：查看特定命令帮助**
```
> /help check

命令: /check
功能: 代码检查

子命令：
  /check /file <path>     - 检查单个文件
  /check /folder <path>   - 检查目录
  /check /resume          - 继续中断的检查
  /check /report          - 查看检查报告

选项：
  --verbose              - 详细输出
  --format json|markdown - 报告格式
  --fix                  - 自动修复问题

示例：
  /check /file src/main.py
  /check /folder src/ --verbose
```

**注意事项**：
- 帮助信息支持中英文
- 可以使用Tab键补全命令名

### 2.2 /exit - 退出命令

**功能**：退出Cuscli程序

**语法**：
```
/exit [options]
```

**选项**：
- `--force` - 强制退出，不保存状态
- `--save` - 保存当前会话后退出

**使用示例**：

**示例1：正常退出**
```
> /exit

? 您有未保存的修改，确定退出？[y/N/s]
  y - 确定退出
  N - 取消
  s - 保存后退出
```

**示例2：保存后退出**
```
> /exit --save
✓ 会话已保存
✓ 正在退出...
```

**示例3：强制退出**
```
> /exit --force
✓ 强制退出，未保存的修改将丢失
```

**快捷键**：
- `Ctrl+D` - 等同于 `/exit`

**注意事项**：
- 退出前会检查是否有未保存的工作
- 后台任务会被自动终止
- 对话历史会自动保存到 `~/.auto-coder/history/`

---

### 2.3 /clear - 清空命令

**功能**：清空当前对话历史

**语法**：
```
/clear [scope]
```

**参数**：
- `scope` - 清空范围，可选值：
  - `all` - 清空所有（默认）
  - `screen` - 仅清空屏幕显示
  - `history` - 仅清空对话历史
  - `context` - 仅清空AI上下文

**使用示例**：

**示例1：清空所有**
```
> /clear
? 确定清空对话历史？[y/N] y
✓ 对话历史已清空
✓ 屏幕已清空
```

**示例2：仅清空屏幕**
```
> /clear screen
✓ 屏幕已清空（对话历史保留）
```

**示例3：仅清空历史**
```
> /clear history
✓ 对话历史已清空（屏幕显示保留）
```

**快捷键**：
- `Ctrl+L` - 清空屏幕（等同于 `/clear screen`）

**注意事项**：
- 清空对话历史后，AI将失去之前的上下文
- 清空屏幕不影响对话历史
- 清空前会提示确认

### 2.4 /config - 配置命令

**功能**：查看和管理配置

**语法**：
```
/config [/subcommand] [arguments] [options]
```

**子命令**：
- `/show` - 显示配置
- `/get <key>` - 获取配置项
- `/set <key> <value>` - 设置配置项
- `/edit` - 编辑配置文件
- `/path` - 显示配置文件路径
- `/validate` - 验证配置文件
- `/reload` - 重新加载配置

**使用示例**：

**示例1：显示所有配置**
```
> /config /show

Cuscli 配置信息
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

AI模型配置:
  model: gpt-4o
  api_key: sk-****...****
  temperature: 0.7

工作环境:
  working_dir: /home/user/project
  python_version: 3.11.5

配置文件: ~/.auto-coder/config.yml
```

**示例2：获取配置项**
```
> /config /get model
gpt-4o

> /config /get code_generation.auto_test
true
```

**示例3：设置配置项**
```
> /config /set temperature 0.8
✓ 配置已更新: temperature = 0.8

> /config /set code_check.parallel 8
✓ 配置已更新
```

**示例4：编辑配置文件**
```
> /config /edit
# 使用默认编辑器打开配置文件

> /config /edit --editor vim
# 使用vim编辑
```

**示例5：验证配置**
```
> /config /validate
✓ 配置文件有效
```

**选项**：
- `--editor <name>` - 指定编辑器
- `--global` - 操作全局配置
- `--local` - 操作项目配置（默认）

**注意事项**：
- 修改某些配置需要重启才能生效
- 敏感信息（如API密钥）会被隐藏显示
- 支持使用环境变量：`ENV {{VAR_NAME}}`

## 第4章 代码检查命令

### 4.1 /check /file - 文件检查

**功能**：检查单个文件的代码质量

**语法**：
```
/check /file <file_path> [options]
```

**参数**：
- `file_path` - 要检查的文件路径（必需）

**选项**：
- `--rules <rules>` - 指定检查规则（逗号分隔）
- `--format <format>` - 报告格式：`markdown`（默认）、`json`、`html`
- `--output <path>` - 输出文件路径
- `--verbose` - 详细输出
- `--fix` - 自动修复问题
- `--fix-interactive` - 交互式修复
- `--only-errors` - 仅显示错误
- `--only <type>` - 仅检查特定类型：`security`、`style`、`performance`

**使用示例**：

**示例1：基本检查**
```
> /check /file src/main.py

✓ 通过项: 8
⚠ 警告项: 3
✗ 错误项: 2

详细报告: .auto-coder/reports/check_main_20251101.md
```

**示例2：指定检查规则**
```
> /check /file src/api.py --rules security,performance

检查规则: security, performance
✓ 安全检查通过
⚠ 性能: 函数复杂度过高 (line 145)
```

**示例3：自动修复**
```
> /check /file src/utils.py --fix

发现 5 个可修复的问题
[1/5] SQL注入风险 ... ✓ 已修复
[2/5] 资源未关闭 ... ✓ 已修复

**示例4：交互式修复**

**示例5：导出特定格式报告**

**示例6：仅检查安全问题**

> /check /file src/api.py --only security

安全检查：

**返回码**：
- `0` - 检查通过，无问题
- `1` - 有警告

**注意事项**：
- 支持相对路径和绝对路径

### 4.2 /check /folder - 目录检查

**功能**：检查整个目录的代码质量

**语法**：
```
/check /folder <dir_path> [options]
```

**参数**：
- `dir_path` - 要检查的目录路径（必需）

**选项**：
- `--recursive` - 递归检查子目录（默认启用）
- `--no-recursive` - 不递归子目录
- `--include <pattern>` - 包含文件模式（如 `*.py`）
- `--exclude <pattern>` - 排除文件模式
- `--parallel <n>` - 并发数（默认4）
- `--max-size <size>` - 最大文件大小（如 `10MB`）
- `--rules <rules>` - 检查规则
- `--format <format>` - 报告格式
- `--output <path>` - 输出路径
- `--fix` - 自动修复所有问题
- `--summary-only` - 仅显示摘要

**使用示例**：

**示例1：基本目录检查**
```
> /check /folder src/

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
检查完成
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

✓ 通过: 18 个文件
