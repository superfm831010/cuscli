## 第1章 安装和配置问题

### Q1.1: 如何安装Cuscli？

**A:**

**方法一：使用wheel包安装（推荐）**
```bash
pip install auto-coder-1.0.39-py3-none-any.whl
```

**方法二：从源码安装**
```bash
pip install -e /path/to/source
```

**验证安装**：
```bash
auto-coder.chat --version
```

**注意事项**：
- 需要Python 3.10-3.12版本
- 建议使用虚拟环境

---

### Q1.2: 安装后提示"command not found"怎么办？

**A:**

**原因**：Python的脚本目录不在PATH中

**解决方案**：

**Linux/macOS**：
```bash
# 方法1：添加到PATH
export PATH="$HOME/.local/bin:$PATH"

# 方法2：使用完整路径
python -m autocoder.chat_auto_coder
```

**Windows**：
```powershell
# 将Python Scripts目录添加到系统PATH
# 通常位于：C:\Users\YourName\AppData\Local\Programs\Python\Python311\Scripts
```

---

### Q1.3: 如何配置AI模型？

**A:**

**编辑配置文件**：`~/.auto-coder/config.yml`

```yaml
# OpenAI模型
model: gpt-4o
api_key: ENV {{OPENAI_API_KEY}}
api_base: https://api.openai.com/v1

# 或使用其他模型
model: claude-3-opus
api_key: ENV {{ANTHROPIC_API_KEY}}
```

**通过环境变量设置**：
```bash
export OPENAI_API_KEY="sk-your-api-key"
```

**通过命令切换模型**：
```bash
> /model /switch gpt-4-turbo
```

---

### Q1.4: 内网环境如何使用？

**A:**

**方案一：配置代理**

```yaml
# config.yml
http_proxy: http://proxy.company.com:8080
https_proxy: http://proxy.company.com:8080
```

**方案二：使用内网部署的模型**

```yaml
model: http://ai-service.internal.com/v1/chat/completions
model_type: openai_compatible
api_key: internal-api-key
```

**方案三：使用本地模型**

参考系统架构说明书中的本地模型部署方案。

---

### Q1.5: 配置文件应该放在哪里？

**A:**

**配置文件优先级**（从高到低）：

1. **项目配置**：`./.auto-coder/config.yml` （最高优先级）
2. **用户配置**：`~/.auto-coder/config.yml`
3. **系统配置**：`/etc/auto-coder/config.yml`

**建议**：
- 团队共享的配置放在项目目录
- 个人配置（如API密钥）放在用户目录

## 第2章 使用问题

### Q2.1: AI生成的代码质量如何保证？

**A:**

**多层保障机制**：

1. **详细的需求描述**
   - 提供充分的上下文
   - 明确技术要求
   - 给出示例

2. **代码检查**
   ```bash
   > /check /file generated_code.py
   ```

3. **测试验证**
   ```bash
   > /test
   ```

4. **人工审查**
   - 仔细阅读生成的代码
   - 理解实现逻辑
   - 进行必要调整

**最佳实践**：
- 从简单开始，逐步细化
- 生成后立即检查
- 编写测试用例验证

### Q2.2: AI生成的代码有错误怎么办？

**A:**

**处理步骤**：

1. **描述问题**
   ```
   > 生成的代码在line 45有语法错误，请修复
   ```

2. **提供更多信息**
   ```
   > 这个函数应该返回列表，但现在返回的是字典，请修正
   ```

3. **重新生成**
   ```
   > 请重新实现这个功能，要求：
     - 使用asyncio
     - 添加错误处理
     - 返回类型为List[User]
   ```

4. **手动修改**
   - 对于简单错误，直接修改
   - 修改后运行代码检查

## 第3章 代码检查问题

### Q3.1: 代码检查需要多长时间？

**A:**

**时间取决于**：
- 文件大小
- 文件数量
- 并发设置
- 网络状况

**参考时间**：
- 单个小文件（<500行）：几秒到十几秒
- 大文件（>1000行）：可能需要分钟级
- 整个目录：取决于文件数量

**加速方法**：
```yaml
# 增加并发数
code_check:
  parallel: 8
```

---

### Q3.2: 检查过程可以中断吗？

**A:**

**可以中断**：
- 按 `Ctrl+C` 中断
- 进度会自动保存

**恢复检查**：
```bash
> /check /resume

# 或列出所有未完成的任务
> /check /resume --list

# 选择特定任务恢复
> /check /resume <task_id>
```

**进度文件位置**：
`.auto-coder/codecheck/progress/`

---

### Q3.3: 自动修复安全吗？

**A:**

**安全机制**：
1. **自动备份**：修复前会备份原文件
2. **交互模式**：可逐项确认修复
3. **查看差异**：修复前可查看改动

**推荐做法**：

**首次使用交互模式**：
```bash
> /check /file src/main.py --fix-interactive
```

**熟悉后使用自动模式**：
```bash
> /check /file src/main.py --fix
```

**重要文件人工审查**：
- 核心业务逻辑
- 安全关键代码
- 复杂算法

**提交前确认**：
```bash
> /git /diff  # 查看所有改动
```

---

**方法一：命令行查看**

**方法二：查看文件**

```bash
# Markdown格式
cat .auto-coder/reports/check_src_20251101.md

# 或在浏览器中打开HTML格式
> /report /export html
# 然后在浏览器打开生成的HTML文件
```

**方法三：导出为其他格式**
```bash
> /report /export pdf

```

---

### Q3.5: 如何忽略某些检查规则？

**A:**

**方法一：禁用规则**
```bash
> /rules /disable security/xss
```

**方法二：在配置中排除**
```yaml
code_check:
  exclude_rules:
    - security/xss
    - style/naming
```

**方法三：指定检查规则**
```bash
> /check /file src/main.py --rules security,performance
```

**临时忽略**（在代码中添加注释）：
```python
# cuscli: ignore-next-line
query = f"SELECT * FROM {table}"
```

## 第4章 Git集成问题

### Q4.1: 如何生成规范的提交信息？

**A:**

**使用智能提交**：
```bash
> /git /commit
```

Cuscli会自动：
1. 分析修改内容
2. 生成符合规范的提交信息
3. 提供预览和确认

**手动指定**：
```bash
> /git /commit -m "feat: 添加用户登录功能"
```

**提交信息规范**：
- `feat:` - 新功能
- `fix:` - bug修复
- `refactor:` - 重构
- `docs:` - 文档更新
- `test:` - 测试相关

---

### Q4.2: 提交前如何自动检查？

**A:**

**使用提交检查**：
```bash

```

**检查内容**：
1. 代码质量检查
2. 运行测试
3. 生成提交信息
4. 确认后提交

**配置自动检查**：
```yaml
git:
  commit_check: true
```

```bash
git clone internal://team-config
cp team-config/config.template.yml .auto-coder/config.yml
```
