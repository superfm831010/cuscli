## 1. 概述

### 1.1 文档目的

本文档旨在为黄埔海关技术人员提供 **Cuscli AI 编程助手平台 v1.1.0** 的详细部署指南，包括环境准备、系统安装、配置管理、启动验证等完整部署流程。通过本文档，系统管理员和运维人员能够独立完成系统在内网环境中的部署与配置。

### 1.2 适用对象

- **系统管理员**：负责服务器环境准备和系统部署
- **运维工程师**：负责系统日常运维和监控
- **技术支持人员**：负责故障排查和问题处理
- **项目实施人员**：负责项目现场部署和交付

### 1.3 适用环境

本部署手册适用于以下环境：

- **生产环境**：黄埔海关内网生产服务器
- **测试环境**：内网测试服务器
- **开发环境**：开发人员工作站

### 1.4 部署架构

Cuscli 平台采用**单机部署架构**，主要包括以下组件：

```
┌─────────────────────────────────────────────┐
│          用户终端（开发人员工作站）              │
│    ┌──────────────────────────────────┐    │
│    │  命令行界面 (CLI)                  │    │
│    │  - cuscli                        │    │
│    │  - chat-auto-coder               │    │
│    └──────────────────────────────────┘    │
└──────────────────┬──────────────────────────┘
                   │ 本地调用
┌──────────────────▼──────────────────────────┐
│         Cuscli 核心系统（本地部署）             │
│  ┌────────────────────────────────────────┐ │
│  │  核心模块                               │ │
│  │  - LLM 集成层                          │ │
│  │  - Agent 系统                          │ │
│  │  - RAG 系统                            │ │
│  │  - 代码检查器                           │ │
│  └────────────────────────────────────────┘ │
│  ┌────────────────────────────────────────┐ │
│  │  配置与数据                             │ │
│  │  - .auto-coder/ (配置目录)             │ │
│  │  - rules/ (检查规则)                   │ │
│  │  - actions/ (动作文件)                 │ │
│  └────────────────────────────────────────┘ │
└──────────────────┬──────────────────────────┘
                   │ API 调用
┌──────────────────▼──────────────────────────┐
│         外部 AI 模型服务（通过代理访问）         │
│  - OpenAI API                              │
│  - Anthropic API                           │
│  - 国产 AI 模型（智谱、通义千问等）           │
└────────────────────────────────────────────┘
```

**说明**：
- Cuscli 平台采用**本地部署**模式，安装在开发人员工作站或内网服务器
- 通过命令行界面与用户交互
- 通过网络代理访问外部 AI 模型 API
- 所有配置和数据存储在本地文件系统

## 2. 部署环境要求

## 3. 安装前准备

### 3.1 环境检查

在开始安装前，请务必完成以下检查：

#### 3.1.1 Linux 环境检查脚本

创建检查脚本 `pre_check_linux.sh`：

```bash
#!/bin/bash
# Cuscli 部署前环境检查脚本 (Linux)

echo "========================================="
echo "  Cuscli 部署前环境检查 (Linux)"
echo "========================================="
echo ""

# 1. 检查操作系统
echo "1. 操作系统信息："
uname -a
cat /etc/os-release | grep PRETTY_NAME
echo ""

# 2. 检查 CPU
echo "2. CPU 信息："
lscpu | grep "Model name"
lscpu | grep "^CPU(s):"
echo ""

# 3. 检查内存
echo "3. 内存信息："
free -h | grep "Mem:"
echo ""

# 4. 检查磁盘空间
echo "4. 磁盘空间："
df -h | grep -E "^/dev/|Filesystem"
echo ""

# 5. 检查 Python 版本
echo "5. Python 版本："
if command -v python3 &> /dev/null; then
    python3 --version
    PY_VERSION=$(python3 -c 'import sys; print(f"{sys.version_info.major}.{sys.version_info.minor}")')
    if [[ "$PY_VERSION" == "3.10" ]] || [[ "$PY_VERSION" == "3.11" ]] || [[ "$PY_VERSION" == "3.12" ]]; then
        echo "✅ Python 版本符合要求 (3.10-3.12)"
    else
        echo "❌ Python 版本不符合要求，需要 3.10-3.12"
    fi
else
    echo "❌ 未安装 Python3"
fi
echo ""

# 6. 检查 pip
echo "6. pip 版本："
if command -v pip3 &> /dev/null; then
    pip3 --version
else
    echo "❌ 未安装 pip3"
fi
echo ""

# 7. 检查 Git
echo "7. Git 版本："
if command -v git &> /dev/null; then
    git --version
else
    echo "❌ 未安装 Git"
fi
echo ""

# 8. 检查网络连通性
echo "8. 网络连通性："
echo -n "  - 内网 DNS: "
if ping -c 1 -W 2 huangpu.customs &> /dev/null; then
    echo "✅ 正常"
else
    echo "⚠️  无法访问"
fi

echo -n "  - 外网访问 (baidu.com): "
if ping -c 1 -W 2 baidu.com &> /dev/null; then
    echo "✅ 正常"
else
    echo "⚠️  无法访问（需配置代理）"
fi
echo ""

# 9. 检查必需命令
echo "9. 必需命令检查："
REQUIRED_CMDS=("gcc" "make" "tar" "gzip")
for cmd in "${REQUIRED_CMDS[@]}"; do
    echo -n "  - $cmd: "
    if command -v $cmd &> /dev/null; then
        echo "✅ 已安装"
    else
        echo "❌ 未安装"
    fi
done
echo ""

echo "========================================="
echo "  检查完成"
echo "========================================="
```

**使用方法**：

```bash
chmod +x pre_check_linux.sh
./pre_check_linux.sh
```

#### 3.1.2 Windows 环境检查脚本

创建检查脚本 `pre_check_windows.ps1`：

```powershell
# Cuscli 部署前环境检查脚本 (Windows)

Write-Host "=========================================" -ForegroundColor Cyan
Write-Host "  Cuscli 部署前环境检查 (Windows)" -ForegroundColor Cyan
Write-Host "=========================================" -ForegroundColor Cyan
Write-Host ""

# 1. 检查操作系统
Write-Host "1. 操作系统信息：" -ForegroundColor Yellow
Get-ComputerInfo | Select-Object WindowsProductName, WindowsVersion, OsArchitecture
Write-Host ""

# 2. 检查 CPU
Write-Host "2. CPU 信息：" -ForegroundColor Yellow
Get-WmiObject -Class Win32_Processor | Select-Object Name, NumberOfCores, NumberOfLogicalProcessors
Write-Host ""

# 3. 检查内存
Write-Host "3. 内存信息：" -ForegroundColor Yellow
$memory = Get-WmiObject -Class Win32_ComputerSystem
$totalMemGB = [math]::Round($memory.TotalPhysicalMemory / 1GB, 2)
Write-Host "  总内存: $totalMemGB GB"
Write-Host ""

# 4. 检查磁盘空间
Write-Host "4. 磁盘空间：" -ForegroundColor Yellow
Get-PSDrive -PSProvider FileSystem | Where-Object {$_.Used -ne $null} |
    Select-Object Name, @{Name="Used(GB)";Expression={[math]::Round($_.Used/1GB,2)}}, @{Name="Free(GB)";Expression={[math]::Round($_.Free/1GB,2)}}
Write-Host ""

# 5. 检查 Python 版本
Write-Host "5. Python 版本：" -ForegroundColor Yellow
try {
    $pyVersion = python --version 2>&1
    Write-Host "  $pyVersion"
    $versionMatch = $pyVersion -match "Python 3\.(10|11|12)\."
    if ($versionMatch) {
        Write-Host "  ✅ Python 版本符合要求 (3.10-3.12)" -ForegroundColor Green
    } else {
        Write-Host "  ❌ Python 版本不符合要求，需要 3.10-3.12" -ForegroundColor Red
    }
} catch {
    Write-Host "  ❌ 未安装 Python" -ForegroundColor Red
}
Write-Host ""

# 6. 检查 pip
Write-Host "6. pip 版本：" -ForegroundColor Yellow
try {
    $pipVersion = pip --version 2>&1
    Write-Host "  $pipVersion"
} catch {
    Write-Host "  ❌ 未安装 pip" -ForegroundColor Red
}
Write-Host ""

# 7. 检查 Git
Write-Host "7. Git 版本：" -ForegroundColor Yellow
try {
    $gitVersion = git --version 2>&1
    Write-Host "  $gitVersion"
} catch {
    Write-Host "  ❌ 未安装 Git" -ForegroundColor Red
}
Write-Host ""

# 8. 检查网络连通性
Write-Host "8. 网络连通性：" -ForegroundColor Yellow
Write-Host -NoNewline "  - 外网访问 (baidu.com): "
if (Test-Connection -ComputerName baidu.com -Count 1 -Quiet) {
    Write-Host "✅ 正常" -ForegroundColor Green
} else {
    Write-Host "⚠️  无法访问（需配置代理）" -ForegroundColor Yellow
}
Write-Host ""

Write-Host "=========================================" -ForegroundColor Cyan
Write-Host "  检查完成" -ForegroundColor Cyan
Write-Host "=========================================" -ForegroundColor Cyan
```

**使用方法**（PowerShell 管理员模式）：

```powershell
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
.\pre_check_windows.ps1
```

```bash
pip install --upgrade pip
```

**Linux/macOS/Windows 通用**：

```bash
# 创建 conda 环境
conda create --name cuscli python=3.10.11 -y

conda activate cuscli

pip install --upgrade pip
```

**优势**：

## 5. 系统配置

### 5.1 配置文件说明

Cuscli 使用 YAML 格式的配置文件进行配置管理。

#### 5.1.1 配置文件位置

| 配置文件 | 路径 | 说明 |
|---------|------|------|
| **项目配置** | `.auto-coder/config.yml` | 项目级配置（优先级最高） |
| **用户配置** | `~/.auto-coder/config.yml` | 用户级配置 |
| **规则配置** | `rules/rules_config.json` | 代码检查规则配置 |
| **动作文件** | `actions/*.yml` | 自动化操作定义 |

#### 5.1.2 配置文件结构

**基本配置文件示例** (`.auto-coder/config.yml`):

```yaml
# Cuscli 配置文件
# 版本: 1.1.0

# ============================================
# 1. 模型配置
# ============================================
model: "gpt-4o-mini"  # 主模型
chat_model: "gpt-4o-mini"  # 聊天模型
code_model: "gpt-4o-mini"  # 代码生成模型
index_model: "gpt-4o-mini"  # 索引模型
emb_model: "text-embedding-3-small"  # 嵌入模型

# ============================================
# 2. API 配置
# ============================================
api_type: "openai"  # API 类型: openai, anthropic, zhipu, dashscope
api_key: "ENV {{OPENAI_API_KEY}}"  # API 密钥（从环境变量读取）
api_base: "https://api.openai.com/v1"  # API 基础 URL

# 代理配置（可选）
# http_proxy: "http://proxy.huangpu.customs:8080"
# https_proxy: "http://proxy.huangpu.customs:8080"

# ============================================
# 3. 项目配置
# ============================================
project_name: "黄埔海关开发项目"
project_path: "."  # 项目根目录
source_dir: "src"  # 源代码目录

# ============================================
# 4. 代码检查配置
# ============================================
checker:
  enabled: true  # 启用代码检查
  rules_dir: "rules"  # 规则目录
  rules_config: "rules/rules_config.json"  # 规则配置文件
  max_workers: 4  # 并发检查线程数
  chunk_size: 500  # 文件分块大小（行数）

# ============================================
# 5. Git 集成配置
# ============================================
git:
  enabled: true  # 启用 Git 集成
  auto_commit: false  # 自动提交（默认关闭）
  commit_message_template: |
    feat: {description}

    由 Cuscli AI 编程助手生成

# ============================================
# 6. 日志配置
# ============================================
log_level: "INFO"  # 日志级别: DEBUG, INFO, WARNING, ERROR
log_file: ".auto-coder/logs/cuscli.log"  # 日志文件路径

# ============================================
# 7. 性能配置
# ============================================
max_tokens: 4096  # 最大 token 数
timeout: 120  # API 请求超时时间（秒）
retry_times: 3  # 重试次数

# ============================================
# 8. 其他配置
# ============================================
language: "zh-CN"  # 界面语言
```

## 8. 常见部署问题及解决方案

### 8.1 安装阶段问题

#### 问题 8.1.1：Python 版本不符合要求

**现象**：
```
ERROR: Package 'cuscli' requires a different Python: 3.9.7 not in '>=3.10,<=3.12'
```

**原因**：Python 版本过低或过高

**解决方案**：

```bash
# 方案1：安装正确版本的 Python
# Ubuntu
sudo apt install python3.10

# 方案2：使用 conda 创建指定版本环境
conda create --name cuscli python=3.10.11
conda activate cuscli
```

#### 问题 8.1.2：依赖包安装失败

**现象**：
```
ERROR: Could not find a version that satisfies the requirement XXX
```

**原因**：
- 网络问题
- 镜像源不可用
- 依赖包版本冲突

**解决方案**：

```bash
# 使用国内镜像源
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple

# 或使用清华镜像
pip install -r requirements.txt -i https://mirrors.tuna.tsinghua.edu.cn/pypi/web/simple

# 或阿里云镜像
pip install -r requirements.txt -i https://mirrors.aliyun.com/pypi/simple/
```

#### 问题 8.1.3：编译扩展包失败（Windows）

**现象**：
```
error: Microsoft Visual C++ 14.0 or greater is required
```

**原因**：缺少 C++ 编译工具

**解决方案**：

1. 下载并安装 Microsoft C++ Build Tools:
   https://visualstudio.microsoft.com/visual-cpp-build-tools/

2. 安装时选择"Desktop development with C++"

3. 重启后重新安装：
   ```cmd
   pip install -r requirements.txt
   ```

#### 问题 8.1.4：权限不足（Linux）

**现象**：
```
PermissionError: [Errno 13] Permission denied: '/usr/local/lib/python3.10/...'
```

**原因**：尝试在系统 Python 环境安装（需要 root 权限）

**解决方案**：

```bash
# 使用虚拟环境（推荐）
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt

# 或使用 --user 参数
pip install -r requirements.txt --user
```

### 8.2 配置阶段问题

#### 问题 8.2.1：API 密钥无效

**现象**：
```
Error: Invalid API key provided
```

**原因**：
- API 密钥错误或过期
- 环境变量未设置

**解决方案**：

```bash
# 1. 检查环境变量
echo $OPENAI_API_KEY  # Linux
echo %OPENAI_API_KEY%  # Windows

# 2. 重新设置
export OPENAI_API_KEY="sk-xxxxxxxxxxxxxxxxxxxxxxxx"  # Linux
$env:OPENAI_API_KEY="sk-xxxxxxxxxxxxxxxxxxxxxxxx"  # Windows

# 3. 验证密钥
curl https://api.openai.com/v1/models \
  -H "Authorization: Bearer $OPENAI_API_KEY"
```

#### 问题 8.2.2：代理配置不生效

**现象**：
```
Error: Connection timeout
Error: Failed to establish a connection
```

**原因**：代理配置错误或代理服务器不可用

**解决方案**：

```bash
# 1. 验证代理服务器可达
curl -x http://proxy.huangpu.customs:8080 https://www.baidu.com

# 2. 检查代理配置
echo $http_proxy
echo $https_proxy

# 3. 测试 API 连接
curl -x http://proxy.huangpu.customs:8080 https://api.openai.com/v1/models \
  -H "Authorization: Bearer $OPENAI_API_KEY"

# 4. 配置 no_proxy（避免内网流量走代理）
export no_proxy="localhost,127.0.0.1,*.huangpu.customs"
```

#### 问题 8.2.3：配置文件格式错误

**现象**：
```
yaml.scanner.ScannerError: mapping values are not allowed here
```

**原因**：YAML 格式错误（缩进、特殊字符等）

**解决方案**：

```bash
# 1. 验证 YAML 格式
python -c "import yaml; yaml.safe_load(open('.auto-coder/config.yml'))"

# 2. 常见错误：
# - 使用 Tab 而非空格缩进（必须使用空格）
# - 字符串包含特殊字符未加引号
# - 冒号后缺少空格

# 3. 使用在线 YAML 验证器检查：
#    https://www.yamllint.com/
```

### 8.3 运行阶段问题

#### 问题 8.3.1：启动失败 - 模块未找到

**现象**：
```
ModuleNotFoundError: No module named 'autocoder'
```

**原因**：
- 未激活虚拟环境
- 安装路径错误

**解决方案**：

```bash
# 1. 确认激活虚拟环境
source venv/bin/activate  # Linux
venv\Scripts\activate.bat  # Windows

# 2. 确认安装位置
pip show cuscli

# 3. 重新安装
pip uninstall cuscli
pip install cuscli-1.1.0-py3-none-any.whl
```

#### 问题 8.3.2：启动失败 - 端口占用

**现象**：
```
OSError: [Errno 98] Address already in use: ('127.0.0.1', 8000)
```

**原因**：端口被其他进程占用（当运行 RAG 服务模式时）

**解决方案**：

```bash
# Linux - 查找并终止占用端口的进程
sudo lsof -i :8000
sudo kill -9 <PID>

# Windows
netstat -ano | findstr :8000
taskkill /PID <PID> /F

# 或使用其他端口
cuscli --port 8001
```

#### 问题 8.3.3：AI 响应超时

**现象**：
```
Error: Request timeout after 120 seconds
```

**原因**：
- 网络延迟高
- API 服务响应慢
- 超时设置过短

**解决方案**：

```yaml
# 增加超时时间（.auto-coder/config.yml）
timeout: 300  # 增加到 5 分钟

# 或在命令行指定
cuscli --timeout 300
```

#### 问题 8.3.4：内存不足

**现象**：
```
MemoryError: Unable to allocate array
```

**原因**：
- 处理大文件
- 并发任务过多

**解决方案**：

```yaml
# 减少并发数（.auto-coder/config.yml）
checker:
  max_workers: 2  # 降低并发数
  chunk_size: 300  # 减小分块大小
```

```bash
# 或增加系统交换空间（Linux）
sudo fallocate -l 4G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
```

### 8.4 功能使用问题

#### 问题 8.4.1：代码检查无结果

**现象**：检查完成但报告为空

**原因**：
- 文件扩展名过滤
- 规则配置问题
- 文件被忽略

**解决方案**：

```bash
# 1. 检查文件是否被扫描
/check /folder /path src /ext .py --verbose

# 2. 检查 .autocoderignore 文件
cat .autocoderignore

# 3. 检查规则配置
cat rules/rules_config.json
```

#### 问题 8.4.2：Git 集成失败

**现象**：
```
Error: Not a git repository
```

**原因**：当前目录不是 Git 仓库

**解决方案**：

```bash
# 1. 检查是否为 Git 仓库
git status

# 2. 如果不是，初始化
git init

# 3. 或切换到正确的项目目录
cd /path/to/git-project
cuscli
```

#### 问题 8.4.3：中文显示乱码（Windows）

**现象**：中文字符显示为乱码或问号

**原因**：终端编码设置问题

**解决方案**：

```cmd
# 设置终端编码为 UTF-8
chcp 65001

# 或在 PowerShell 中：
$OutputEncoding = [System.Text.Encoding]::UTF8
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
```

### 8.5 性能优化问题

#### 问题 8.5.1：响应速度慢

**原因及解决方案**：

| 原因 | 解决方案 |
|------|---------|
| 网络延迟高 | 使用国内 API 服务（智谱、通义千问）|
| 模型选择不当 | 使用更快的模型（gpt-4o-mini） |
| 代理性能差 | 优化代理配置或使用直连 |
| 并发度低 | 增加 `max_workers` 配置 |

```yaml
# 性能优化配置
model: "gpt-4o-mini"  # 使用快速模型
timeout: 60  # 适当的超时时间
checker:
  max_workers: 8  # 增加并发数（根据 CPU 核心数）
```

#### 问题 8.5.2：磁盘空间不足

**现象**：
```
OSError: [Errno 28] No space left on device
```

**解决方案**：

```bash
# 1. 清理日志文件
find .auto-coder/logs -name "*.log" -mtime +7 -delete

# 2. 清理缓存
rm -rf .auto-coder/cache/*

# 3. 清理旧的检查点文件
rm -rf .auto-coder/checkpoints/*

# 4. 配置日志轮转
```

```yaml
# .auto-coder/config.yml
log_rotate:
  enabled: true
  max_bytes: 10485760  # 10 MB
  backup_count: 5
```

```
/home/user/myproject/  (Linux) 或 C:\Users\user\myproject\  (Windows)
├── .auto-coder/                 # Cuscli 配置和数据目录
│   ├── config.yml               # 项目配置文件
│   ├── logs/                    # 日志目录
│   │   └── cuscli.log
```

### 10.3 日志文件说明

| 日志文件 | 路径 | 内容 | 轮转策略 |
|---------|------|------|---------|

- `INFO`：一般信息（默认）
- `WARNING`：警告信息
- `ERROR`：错误信息
- `CRITICAL`：严重错误
