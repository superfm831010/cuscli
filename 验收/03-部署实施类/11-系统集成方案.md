## 1. 概述

### 1.1 文档目的

本文档旨在为黄埔海关技术人员提供 **Cuscli AI 编程助手平台 v1.1.0** 与现有开发工具、平台和系统的集成方案。通过本文档，开发人员和系统管理员能够将 Cuscli 无缝集成到现有的开发环境中，实现高效协同工作。

### 1.2 适用对象

- **开发人员**：使用 IDE 进行日常开发工作
- **DevOps 工程师**：负责 CI/CD 流程集成
- **系统管理员**：负责开发环境管理和维护
- **技术负责人**：负责技术架构和工具选型

### 1.3 集成架构

Cuscli 平台支持多种集成方式，可与现有开发工具链无缝对接：


## 2. IDE 集成方案

### 2.1 Visual Studio Code 集成

Visual Studio Code (VSCode) 是目前最流行的代码编辑器之一，Cuscli 可以通过终端集成的方式在 VSCode 中使用。

#### 2.1.1 集成架构

```
┌──────────────────────────────────────────────┐
│           Visual Studio Code                 │
│                                               │
│  ┌──────────────────────────────────────┐   │

│  │  - 代码编辑                          │   │

│  │  - 代码补全                          │   │
│  └──────────────────────────────────────┘   │
│                                               │
│  ┌──────────────────────────────────────┐   │
│  │      集成终端 (Integrated Terminal)   │   │
│  │  ┌────────────────────────────────┐  │   │
│  │  │  $ cuscli                      │  │   │
│  │  │  >>> /check /file main.py      │  │   │

│  │  └────────────────────────────────┘  │   │

└──────────────────────────────────────────────┘
```

#### 2.1.2 集成步骤

**步骤 1：打开 VSCode 终端**

在 VSCode 中打开集成终端：
- 快捷键：`` Ctrl+` ``（Windows/Linux）或 `` Cmd+` ``（macOS）
- 或菜单：`Terminal` → `New Terminal`

**步骤 2：激活虚拟环境**

在终端中激活 Cuscli 虚拟环境：

```bash
# Linux/macOS
source /opt/cuscli/venv/bin/activate

# Windows
C:\cuscli\venv\Scripts\activate.bat

# 或使用 conda
conda activate cuscli
```

**步骤 3：启动 Cuscli**

```bash
# 在当前项目目录启动
cuscli

# 或指定项目目录
cuscli --project /path/to/project
```

**步骤 4：使用 Cuscli**

在 Cuscli 命令行中执行各种操作：

```bash
>>> /help                          # 查看帮助
>>> /check /file src/main.py       # 检查当前编辑的文件
>>> /git status                    # 查看 Git 状态
>>> 请帮我优化这段代码...           # AI 对话
```

**典型工作流**：

3. 激活虚拟环境并启动 Cuscli

### 2.2 PyCharm / IntelliJ IDEA 集成

PyCharm 是专业的 Python IDE，Cuscli 可以通过 PyCharm 的终端工具窗口集成使用。

#### 2.2.1 集成步骤

**步骤 1：配置 Python 解释器**

1. 打开 `File` → `Settings` → `Project` → `Python Interpreter`
2. 点击齿轮图标 → `Add...`
3. 选择 `Existing environment`
4. 选择 Cuscli 虚拟环境的 Python 解释器：
   - Linux: `/opt/cuscli/venv/bin/python`
   - Windows: `C:\cuscli\venv\Scripts\python.exe`
5. 点击 `OK`

**步骤 2：打开终端工具窗口**

- 快捷键：`Alt+F12`
- 或菜单：`View` → `Tool Windows` → `Terminal`

**步骤 3：启动 Cuscli**

在终端中直接运行：

```bash
cuscli
```

由于已配置项目解释器，Cuscli 会自动使用正确的虚拟环境。

#### 2.2.2 配置外部工具（External Tools）

在 PyCharm 中配置 Cuscli 为外部工具，方便快速调用。

**配置步骤**：

1. 打开 `File` → `Settings` → `Tools` → `External Tools`
2. 点击 `+` 添加新工具
3. 配置如下：

**工具 1：Cuscli 检查当前文件**

```
Name: Cuscli 检查当前文件
Program: $PyInterpreterDirectory$/cuscli
Arguments: --check-file $FilePath$
Working directory: $ProjectFileDir$
```

**工具 2：Cuscli 检查当前目录**

```
Name: Cuscli 检查当前目录
Program: $PyInterpreterDirectory$/cuscli
Arguments: --check-folder $FileDir$
Working directory: $ProjectFileDir$
```

**使用方法**：
1. 在编辑器中右键点击文件或目录
2. 选择 `External Tools` → `Cuscli 检查当前文件`

#### 2.2.3 配置快捷键

为外部工具配置快捷键：

1. 打开 `File` → `Settings` → `Keymap`
2. 搜索 `External Tools`
3. 找到配置的 Cuscli 工具
4. 右键 → `Add Keyboard Shortcut`
5. 设置快捷键（如 `Ctrl+Alt+C`）

### 2.3 其他 IDE 集成

#### 2.3.1 Eclipse 集成

通过 Eclipse 的终端插件集成：

1. 安装 `TM Terminal` 插件
2. 打开 `Window` → `Show View` → `Terminal`
3. 在终端中激活虚拟环境并启动 Cuscli

通过 Build System 集成：

创建 `Tools` → `Build System` → `New Build System`：

```json

  "cmd": ["cuscli", "--check-file", "$file"],
  "selector": "source.python",
  "shell": true
}
```

保存为 `Cuscli.sublime-build`，按 `Ctrl+B` 执行。

在 `.vimrc` 或 `init.vim` 中添加：

#### 3.1.3 GitLab CI/CD 集成

通过 GitLab CI/CD 自动运行 Cuscli 代码检查。

**步骤 1：准备 Cuscli 运行环境**

在 GitLab Runner 服务器上安装 Cuscli：

```bash
# 安装 Python 3.10+
sudo apt install python3.10 python3.10-venv

# 创建虚拟环境
python3.10 -m venv /opt/cuscli/venv

# 激活并安装
source /opt/cuscli/venv/bin/activate
pip install cuscli-1.1.0-py3-none-any.whl
```

**步骤 2：配置 GitLab CI/CD**

在项目根目录创建 `.gitlab-ci.yml`：

```yaml
# GitLab CI/CD 配置 - Cuscli 代码检查

stages:
  - test
  - build

# Cuscli 代码检查 Job
cuscli-check:
  stage: test
  image: python:3.10
  before_script:
    # 安装 Cuscli（使用项目内的安装包或从仓库获取）
    - pip install cuscli
    # 或从私有仓库安装
    # - pip install cuscli --extra-index-url http://pypi.huangpu.customs/simple
  script:
    # 创建配置文件
    - mkdir -p .auto-coder
    - |
      cat > .auto-coder/config.yml << EOF
      model: "gpt-4o-mini"
      api_type: "openai"
      api_key: "ENV {{OPENAI_API_KEY}}"
      api_base: "${OPENAI_API_BASE}"
      http_proxy: "${HTTP_PROXY}"
      https_proxy: "${HTTPS_PROXY}"
      checker:
        enabled: true
        rules_dir: "rules"
        rules_config: "rules/rules_config.json"
        max_workers: 2
      EOF

    # 执行代码检查
    - cuscli --check-folder src --output-report .auto-coder/reports/check-report.json

    # 检查是否有严重问题（可选，用于阻断流水线）
    - |
      python3 << EOF
      import json
      with open('.auto-coder/reports/check-report.json') as f:
          report = json.load(f)
      critical_count = sum(1 for issue in report.get('issues', []) if issue.get('severity') == 'critical')
      if critical_count > 0:
          print(f"发现 {critical_count} 个严重问题，阻断流水线！")
          exit(1)
      EOF

  artifacts:
    paths:
      - .auto-coder/reports/
    expire_in: 1 week
    reports:
      junit: .auto-coder/reports/check-report.xml  # 如果生成 JUnit 格式报告

  only:
    - merge_requests
    - main
    - develop

  variables:
    # 从 GitLab CI/CD 变量中读取（需在 GitLab 项目设置中配置）
    OPENAI_API_KEY: $OPENAI_API_KEY
    OPENAI_API_BASE: $OPENAI_API_BASE
    HTTP_PROXY: $HTTP_PROXY
    HTTPS_PROXY: $HTTPS_PROXY

# 构建 Job（示例）
build:
  stage: build
  script:
    - echo "构建项目..."
  only:
    - main
```

**步骤 3：配置 GitLab CI/CD 变量**

在 GitLab 项目设置中配置环境变量：

1. 进入项目 → `Settings` → `CI/CD` → `Variables`
2. 添加以下变量：
   - `OPENAI_API_KEY`：OpenAI API 密钥（Masked）
   - `OPENAI_API_BASE`：API 基础 URL
   - `HTTP_PROXY`：代理服务器地址
   - `HTTPS_PROXY`：代理服务器地址

**步骤 4：测试 CI/CD**

1. 创建新分支并推送代码
2. 创建 Merge Request
3. 查看 CI/CD 流水线执行结果
4. 下载检查报告查看详细结果

#### 3.1.4 Merge Request 自动审查

通过 GitLab Webhook 实现 Merge Request 自动审查。

**方案 1：使用 GitLab CI/CD**（推荐）

在 `.gitlab-ci.yml` 中添加评论 Job：

```yaml
cuscli-comment:
  stage: test
  image: python:3.10
  script:
    # 执行检查并生成 Markdown 报告
    - cuscli --check-folder src --output-report .auto-coder/reports/check-report.md

    # 将报告作为评论发布到 Merge Request
    - |
      REPORT=$(cat .auto-coder/reports/check-report.md)
      curl --request POST \
        --header "PRIVATE-TOKEN: ${GITLAB_API_TOKEN}" \
        "${CI_API_V4_URL}/projects/${CI_PROJECT_ID}/merge_requests/${CI_MERGE_REQUEST_IID}/notes" \
        --data-urlencode "body=## Cuscli 代码检查报告\n\n${REPORT}"

  only:
    - merge_requests

  variables:
    GITLAB_API_TOKEN: $GITLAB_API_TOKEN  # 需在 GitLab 设置
```

**方案 2：使用独立服务**

部署一个独立的 Webhook 服务，监听 GitLab Merge Request 事件。

### 3.2 GitHub 集成

#### 3.2.1 GitHub Actions 集成

创建 `.github/workflows/cuscli-check.yml`：

```yaml
name: Cuscli 代码检查

on:
  push:
    branches: [ main, develop ]
  pull_request:
    branches: [ main, develop ]

jobs:
  cuscli-check:
    runs-on: ubuntu-latest

    steps:
    - name: 检出代码
      uses: actions/checkout@v3

    - name: 设置 Python 3.10
      uses: actions/setup-python@v4
      with:
        python-version: '3.10'

    - name: 安装 Cuscli
      run: |
        python -m pip install --upgrade pip
        pip install cuscli

    - name: 创建配置文件
      run: |
        mkdir -p .auto-coder
        cat > .auto-coder/config.yml << EOF
        model: "gpt-4o-mini"
        api_type: "openai"
        api_key: "ENV {{OPENAI_API_KEY}}"
        api_base: "${{ secrets.OPENAI_API_BASE }}"
        http_proxy: "${{ secrets.HTTP_PROXY }}"
        https_proxy: "${{ secrets.HTTPS_PROXY }}"
        checker:
          enabled: true
          rules_dir: "rules"
          rules_config: "rules/rules_config.json"
          max_workers: 2
        EOF

    - name: 执行代码检查
      env:
        OPENAI_API_KEY: ${{ secrets.OPENAI_API_KEY }}
      run: |
        cuscli --check-folder src --output-report .auto-coder/reports/check-report.md

    - name: 上传检查报告
      uses: actions/upload-artifact@v3
      with:
        name: cuscli-report
        path: .auto-coder/reports/

    - name: 发布检查结果为评论（Pull Request）
      if: github.event_name == 'pull_request'
      uses: actions/github-script@v6
      with:
        script: |
          const fs = require('fs');
          const report = fs.readFileSync('.auto-coder/reports/check-report.md', 'utf8');
          github.rest.issues.createComment({
            issue_number: context.issue.number,
            owner: context.repo.owner,
            repo: context.repo.repo,
            body: `## Cuscli 代码检查报告\n\n${report}`
          });
```

**配置 GitHub Secrets**：

1. 进入仓库 → `Settings` → `Secrets and variables` → `Actions`
2. 添加以下 Secrets：
   - `OPENAI_API_KEY`
   - `OPENAI_API_BASE`
   - `HTTP_PROXY`
   - `HTTPS_PROXY`

#### 3.2.2 Pre-commit Hook 集成

在本地使用 Git Pre-commit Hook 在提交前自动检查代码。

**创建 Pre-commit Hook**

在项目根目录创建 `.git/hooks/pre-commit`：

```bash
#!/bin/bash
# Cuscli Pre-commit Hook

echo "🔍 运行 Cuscli 代码检查..."

# 激活虚拟环境
source venv/bin/activate 2>/dev/null || source /opt/cuscli/venv/bin/activate

# 获取暂存的文件
STAGED_FILES=$(git diff --cached --name-only --diff-filter=ACM | grep -E '\.(py|js|jsx|ts|tsx|java)$')

if [ -z "$STAGED_FILES" ]; then
    echo "✅ 没有需要检查的文件"
    exit 0
fi

# 检查每个文件
HAS_ERRORS=0
for FILE in $STAGED_FILES; do
    echo "检查: $FILE"
    cuscli --check-file "$FILE" --quiet
    if [ $? -ne 0 ]; then
        HAS_ERRORS=1
    fi
done

if [ $HAS_ERRORS -eq 1 ]; then
    echo ""
    echo "❌ 代码检查发现问题，请修复后再提交"
    echo "提示：使用 'git commit --no-verify' 可跳过检查（不推荐）"
    exit 1
fi

echo "✅ 代码检查通过"
exit 0
```

#### 5.1.1 批量检查脚本

创建 `check-all.sh`：

```bash
#!/bin/bash
# 批量检查项目脚本

set -e

# 颜色定义
RED='\033[0;31m'
GREEN='\033[0;32m'
YELLOW='\033[1;33m'
NC='\033[0m' # No Color

# 配置
PROJECTS_DIR="/home/projects"
REPORT_DIR="/var/cuscli-reports"
TIMESTAMP=$(date +%Y%m%d_%H%M%S)

echo "======================================"
echo "  Cuscli 批量代码检查"
echo "======================================"
echo ""

# 激活虚拟环境
source /opt/cuscli/venv/bin/activate

# 创建报告目录
mkdir -p "$REPORT_DIR/$TIMESTAMP"

# 遍历项目
for project in "$PROJECTS_DIR"/*; do
    if [ -d "$project" ]; then
        project_name=$(basename "$project")
        echo "检查项目: $project_name"

        cd "$project"

        # 检查是否有规则配置
        if [ ! -f "rules/rules_config.json" ]; then
            echo -e "${YELLOW}⚠️  跳过 $project_name：未配置检查规则${NC}"
            continue
        fi

        # 执行检查
        report_file="$REPORT_DIR/$TIMESTAMP/${project_name}-report.json"
        if cuscli --check-folder . --output-report "$report_file" --quiet; then
            echo -e "${GREEN}✅ $project_name 检查通过${NC}"
        else
            echo -e "${RED}❌ $project_name 检查失败${NC}"
        fi

        echo ""
    fi
done

# 生成汇总报告
echo "生成汇总报告..."
python3 << EOF
import json
import os
from pathlib import Path

report_dir = Path("$REPORT_DIR/$TIMESTAMP")
reports = list(report_dir.glob("*-report.json"))

total_issues = 0
critical_count = 0
high_count = 0

for report_file in reports:
    with open(report_file) as f:
        report = json.load(f)
    issues = report.get('issues', [])
    total_issues += len(issues)
    critical_count += sum(1 for i in issues if i.get('severity') == 'critical')
    high_count += sum(1 for i in issues if i.get('severity') == 'high')

print(f"检查完成：共检查 {len(reports)} 个项目")
print(f"发现问题：{total_issues} 个（严重: {critical_count}, 高级: {high_count}）")

# 保存汇总
summary = {
    'timestamp': '$TIMESTAMP',
    'projects_count': len(reports),
    'total_issues': total_issues,
    'critical_count': critical_count,
    'high_count': high_count,
    'reports': [str(r.name) for r in reports]
}
with open(report_dir / 'summary.json', 'w') as f:
    json.dump(summary, f, indent=2)
EOF

echo ""
echo "报告已保存到: $REPORT_DIR/$TIMESTAMP"
echo "======================================"
```

```python
from django.core.management.base import BaseCommand
from autocoder.checker.core import CodeChecker
from autocoder.checker.rules_loader import RulesLoader
from autocoder.common.llms import LLMManager
import os

class Command(BaseCommand):
    help = '运行 Cuscli 代码检查'

    def add_arguments(self, parser):
        parser.add_argument(
            '--path',
            type=str,
            default='.',
            help='检查的路径'
        )
        parser.add_argument(
            '--rules',
            type=str,
            default='rules/rules_config.json',
            help='规则配置文件'
        )

    def handle(self, *args, **options):
        self.stdout.write(self.style.SUCCESS('开始 Cuscli 代码检查...'))

        # 初始化
        llm_manager = LLMManager(
            model=os.getenv('CUSCLI_MODEL', 'gpt-4o-mini'),
            api_key=os.getenv('OPENAI_API_KEY'),
        )

        rules_loader = RulesLoader(options['rules'])
        rules = rules_loader.load_rules()

        checker = CodeChecker(llm_manager=llm_manager, rules=rules)

        # 执行检查
        path = options['path']
        if os.path.isfile(path):
            result = checker.check_file(path)
            issues_count = len(result['issues'])
        else:
            results = checker.check_folder(path)
            issues_count = sum(len(r['issues']) for r in results.values())

        # 输出结果
        if issues_count == 0:
            self.stdout.write(self.style.SUCCESS(f'✅ 检查完成，未发现问题'))
        else:
            self.stdout.write(self.style.WARNING(f'⚠️  检查完成，发现 {issues_count} 个问题'))
```

```python
from fastapi import FastAPI, UploadFile, File
from autocoder.checker.core import CodeChecker

    # 清理

@app.get("/health")

    """健康检查"""
```

## 8. 常见集成问题及解决方案

### 8.1 IDE 集成问题

**问题 8.1.1：VSCode 终端中找不到 cuscli 命令**

**原因**：虚拟环境未激活或 PATH 配置错误

**解决方案**：

```bash
# 检查虚拟环境
which cuscli  # Linux/macOS
where cuscli  # Windows

# 手动激活虚拟环境
source /opt/cuscli/venv/bin/activate  # Linux/macOS
C:\cuscli\venv\Scripts\activate.bat   # Windows
```

**问题 8.1.2：PyCharm 外部工具无法运行**

**原因**：Python 解释器路径错误

**解决方案**：

1. 检查 `Program` 路径是否正确
2. 使用 `$PyInterpreterDirectory$/cuscli` 而不是绝对路径
3. 确认项目 Python 解释器配置正确

### 8.2 Git 集成问题

**问题 8.2.1：CI/CD 流水线中 API 调用超时**

**原因**：网络配置或代理设置问题

**解决方案**：

```yaml
# 在 CI/CD 配置中增加超时设置
script:
  - export CUSCLI_TIMEOUT=300
  - cuscli --check-folder src --timeout 300
```

**问题 8.2.2：Pre-commit Hook 执行失败**

**原因**：Hook 脚本权限不足或虚拟环境路径错误

**解决方案**：

```bash
# 检查权限
chmod +x .git/hooks/pre-commit

# 检查脚本中的虚拟环境路径
cat .git/hooks/pre-commit
```

### 8.3 CI/CD 集成问题

**问题 8.3.1：Jenkins 构建中安装 Cuscli 失败**

**原因**：网络问题或 pip 源配置

**解决方案**：

```bash
# 使用国内镜像源
pip install cuscli -i https://pypi.tuna.tsinghua.edu.cn/simple

# 或使用离线安装包
pip install /path/to/cuscli-1.1.0-py3-none-any.whl
```

**问题 8.3.2：报告解析失败**

**原因**：报告格式不匹配或文件不存在

**解决方案**：

```bash
# 检查报告文件是否存在
ls -la .auto-coder/reports/

# 验证 JSON 格式
python -m json.tool .auto-coder/reports/check-report.json
```
