## 第2章 系统部署与配置

### 2.1 部署前准备

#### 2.1.1 环境检查

**硬件要求检查**：

| 资源 | 最低要求 | 推荐配置 |
|------|---------|---------|
| CPU | 2核 | 4核及以上 |
| 内存 | 4GB | 8GB及以上 |
| 磁盘 | 20GB | 50GB及以上 |
| 网络 | 稳定的网络连接 | 带宽≥10Mbps |

**操作系统要求**：
- Linux：Ubuntu 20.04+、CentOS 7+、银河麒麟、统信UOS
- Windows：Windows 10/11、Windows Server 2016+

**软件依赖**：
- Python 3.10-3.12
- pip 包管理器
- Git（可选）

#### 2.1.2 网络规划

**内网部署考虑**：
- 确认内网AI模型服务地址
- 配置代理服务器（如需要）
- 检查防火墙规则

**端口规划**（如需开放服务）：
- 建议使用标准端口
- 配置防火墙规则
- 记录端口分配

### 2.2 系统安装

#### 2.2.1 安装步骤

**方式一：Wheel包安装（推荐）**

```bash
# 1. 准备Python环境
python3 --version  # 确认版本

# 2. 创建虚拟环境（推荐）
python3 -m venv /opt/cuscli-env
source /opt/cuscli-env/bin/activate

# 3. 安装Wheel包
pip install auto-coder-1.0.39-py3-none-any.whl

# 4. 验证安装
auto-coder.chat --version
```

**方式二：离线安装**

```bash
# 1. 准备离线安装包
# 包含：wheel包、依赖包

# 2. 安装依赖
pip install --no-index --find-links=/path/to/packages -r requirements.txt

# 3. 安装主程序
pip install --no-index --find-links=/path/to/packages auto-coder-1.0.39-py3-none-any.whl
```

#### 2.2.2 安装验证

**基本验证**：
```bash
# 检查安装
pip show auto-coder

# 测试启动
auto-coder.chat --help
```

### 2.3 系统配置

#### 2.3.1 配置文件管理

**配置文件位置**：

```
全局配置：/etc/auto-coder/config.yml
用户配置：~/.auto-coder/config.yml
项目配置：./.auto-coder/config.yml
```

**优先级**：项目配置 > 用户配置 > 全局配置

**配置文件结构**：

```yaml
# AI模型配置
model: gpt-4o
api_key: ENV {{OPENAI_API_KEY}}
api_base: https://api.openai.com/v1

# 代理配置（内网环境）
http_proxy: http://proxy.company.com:8080
https_proxy: http://proxy.company.com:8080

# 代码生成设置
code_generation:
  language: Python
  auto_test: true
  auto_comment: true

# 代码检查设置
code_check:
  max_file_size: 10485760  # 10MB
  parallel: 4
  report_format: markdown

# 日志配置
log_level: INFO
log_file: ~/.auto-coder/logs/auto-coder.log
```

#### 2.3.2 环境变量配置

**推荐的环境变量**：

```bash
# AI模型配置
export OPENAI_API_KEY="sk-your-api-key"
export ANTHROPIC_API_KEY="sk-ant-your-key"

# 内网代理
export HTTP_PROXY="http://proxy:8080"
export HTTPS_PROXY="http://proxy:8080"

# 自定义配置路径
export AUTO_CODER_CONFIG="/etc/auto-coder/config.yml"
```

**持久化配置**（Linux）：

```bash
# 添加到 /etc/profile.d/cuscli.sh
cat > /etc/profile.d/cuscli.sh << 'EOF'
export OPENAI_API_KEY="ENV_VALUE"
export HTTP_PROXY="http://proxy:8080"
EOF

chmod +x /etc/profile.d/cuscli.sh
```

#### 2.3.3 内网环境配置

**配置内网AI服务**：

```yaml
# config.yml
model: http://ai-service.internal.com/v1/chat/completions
model_type: openai_compatible
api_key: internal-api-key
api_base: http://ai-service.internal.com/v1
```

**配置代理**：

```yaml
http_proxy: http://proxy.company.com:8080
https_proxy: http://proxy.company.com:8080
no_proxy: localhost,127.0.0.1,.company.com
```

### 2.4 多用户部署

#### 2.4.1 集中式部署

**在服务器上部署**：

```bash
# 1. 创建共享安装目录
sudo mkdir -p /opt/cuscli
sudo python3 -m venv /opt/cuscli/env

# 2. 安装
sudo /opt/cuscli/env/bin/pip install auto-coder-1.0.39-py3-none-any.whl

# 3. 创建启动脚本
sudo cat > /usr/local/bin/cuscli << 'EOF'
#!/bin/bash
source /opt/cuscli/env/bin/activate
auto-coder.chat "$@"
EOF

sudo chmod +x /usr/local/bin/cuscli

# 4. 用户可直接使用
cuscli
```

#### 2.4.2 配置模板管理

**创建团队配置模板**：

```bash
# 1. 准备配置模板
mkdir -p /opt/cuscli/templates

# 2. 创建基础配置
cat > /opt/cuscli/templates/config.template.yml << 'EOF'
model: gpt-4o
api_key: ENV {{OPENAI_API_KEY}}
code_generation:
  language: Python
  auto_test: true
EOF

# 3. 用户初始化
cp /opt/cuscli/templates/config.template.yml ~/.auto-coder/config.yml
```

## 第3章 用户与权限管理

### 3.1 用户账号管理

#### 3.1.1 添加用户

**Linux系统**：

```bash
# 创建用户
sudo useradd -m -s /bin/bash cuscli-user

# 设置密码
sudo passwd cuscli-user

# 添加到开发组
sudo usermod -aG developers cuscli-user
```

#### 3.1.2 用户配置初始化

**为新用户初始化配置**：

```bash
# 创建配置目录
sudo -u cuscli-user mkdir -p /home/cuscli-user/.auto-coder

# 复制配置模板
sudo cp /opt/cuscli/templates/config.template.yml \
    /home/cuscli-user/.auto-coder/config.yml

# 设置权限
sudo chown -R cuscli-user:cuscli-user /home/cuscli-user/.auto-coder
```

### 3.2 权限配置

#### 3.2.1 文件权限

**推荐的权限设置**：

```bash
# 安装目录（只读）
chmod 755 /opt/cuscli
chmod 755 /opt/cuscli/env

# 用户配置（用户可写）
chmod 700 ~/.auto-coder
chmod 600 ~/.auto-coder/config.yml

# 日志目录（用户可写）
chmod 755 ~/.auto-coder/logs
chmod 644 ~/.auto-coder/logs/*.log

# 缓存目录（用户可写）
chmod 755 ~/.auto-coder/cache
```

#### 3.2.2 资源限制

**配置用户资源限制**（可选）：

```bash
# 编辑 /etc/security/limits.conf
cuscli-user soft nproc 100
cuscli-user hard nproc 200
cuscli-user soft nofile 1024
cuscli-user hard nofile 2048
```

### 3.3 API密钥管理

#### 3.3.1 密钥分发

**推荐的密钥管理方式**：

**方式一：环境变量**
```bash
# 为每个用户设置独立的密钥
echo 'export OPENAI_API_KEY="user-specific-key"' >> ~/.bashrc
```

**方式二：配置文件**
```yaml
# ~/.auto-coder/config.yml
api_key: ENV {{OPENAI_API_KEY}}
```

**方式三：密钥服务器**（企业级）
- 使用内部密钥管理服务
- 通过API动态获取密钥

#### 3.3.2 密钥安全

**安全建议**：
- 不要将密钥硬编码在配置文件中
- 使用环境变量或密钥服务
- 定期轮换密钥
- 设置密钥使用限额
- 监控密钥使用情况

## 第5章 备份与恢复

### 5.1 备份策略

#### 5.1.1 备份内容

**需要备份的内容**：

| 内容 | 路径 | 重要性 | 备份频率 |
|------|------|--------|---------|
| 配置文件 | `~/.auto-coder/config.yml` | 高 | 修改后立即 |
| 自定义规则 | `~/.auto-coder/rules/` | 高 | 每周 |
| 历史会话 | `~/.auto-coder/history/` | 中 | 每天 |
| 检查报告 | `~/.auto-coder/reports/` | 中 | 每周 |
| 项目配置 | `./.auto-coder/` | 高 | 提交到Git |

**不需要备份的内容**：
- 日志文件（可重新生成）
- 缓存文件（可重新生成）
- 临时文件

#### 5.1.2 备份方法

**方式一：手动备份**

```bash
#!/bin/bash
# backup.sh - 备份脚本

BACKUP_DIR="/backup/cuscli"
DATE=$(date +%Y%m%d)

# 创建备份目录
mkdir -p $BACKUP_DIR/$DATE

# 备份配置和规则
cp -r ~/.auto-coder/config.yml $BACKUP_DIR/$DATE/
cp -r ~/.auto-coder/rules/ $BACKUP_DIR/$DATE/

# 备份历史会话
cp -r ~/.auto-coder/history/ $BACKUP_DIR/$DATE/

# 压缩备份
cd $BACKUP_DIR
tar -czf cuscli-backup-$DATE.tar.gz $DATE/
rm -rf $DATE/

echo "备份完成: $BACKUP_DIR/cuscli-backup-$DATE.tar.gz"
```

**方式二：自动备份**

```bash
# 添加到crontab
crontab -e

# 每天凌晨2点备份
0 2 * * * /path/to/backup.sh
```

### 5.2 恢复操作

#### 5.2.1 恢复步骤

**恢复配置和数据**：

```bash
#!/bin/bash
# restore.sh - 恢复脚本

BACKUP_FILE="/backup/cuscli/cuscli-backup-20251101.tar.gz"

# 解压备份
cd /tmp

# 恢复配置
cp -r /tmp/20251101/config.yml ~/.auto-coder/
cp -r /tmp/20251101/rules/ ~/.auto-coder/

# 恢复历史
cp -r /tmp/20251101/history/ ~/.auto-coder/

# 清理临时文件
rm -rf /tmp/20251101

echo "恢复完成"
```

#### 5.2.2 验证恢复

**验证恢复结果**：

```bash

# 2. 检查规则文件

# 3. 测试启动

# 4. 检查配置
```

## 第6章 故障诊断与处理

### 6.1 常见问题诊断

#### 6.1.1 启动失败

**症状**：程序无法启动

**诊断步骤**：

```bash
# 1. 检查安装
pip show auto-coder

# 2. 检查Python版本
python --version

# 3. 检查依赖
pip check

# 4. 查看错误日志
tail -50 ~/.auto-coder/logs/auto-coder.log
```

**常见原因及解决**：
- Python版本不符 → 安装正确版本
- 依赖缺失 → 重新安装
- 配置文件错误 → 验证配置语法

#### 6.1.2 连接问题

**症状**：无法连接AI模型

**诊断步骤**：

```bash
# 1. 测试网络连接
ping api.openai.com
curl -I https://api.openai.com

# 2. 检查代理配置
echo $HTTP_PROXY
echo $HTTPS_PROXY

# 3. 验证API密钥
# 查看配置中的API密钥设置

# 4. 查看详细日志
auto-coder.chat --debug
```

**解决方法**：
- 配置正确的代理
- 检查防火墙规则
- 验证API密钥有效性
- 使用内网AI服务

#### 6.1.3 性能问题

**症状**：运行缓慢

**诊断步骤**：

```bash
# 1. 检查系统资源
top
free -h
df -h

# 2. 检查进程状态
ps aux | grep auto-coder

# 3. 查看日志
grep "slow\|timeout" ~/.auto-coder/logs/auto-coder.log
```

**优化建议**：
- 清理缓存和日志
- 增加系统资源
- 调整并发配置
- 优化网络连接

### 6.2 故障处理流程
