## 2. 规则配置文件

### 2.1 规则配置文件概述

**文件名**: `rules/rules_config.json`

**用途**: 配置代码检查规则的启用/禁用、文件匹配模式、严重级别等

**格式**: JSON

**位置**: 项目根目录下的 `rules/` 目录

### 2.2 规则配置文件结构

#### 2.2.1 完整示例

```json
{
  "version": "1.0.0",
  "description": "代码检查规则配置文件",

  "rule_sets": {
    "backend": {
      "enabled": true,
      "file_patterns": [
        "**/*.py",
        "**/*.java"
      ],
      "severity_threshold": "warning",
      "disabled_rules": [],
      "description": "Python/Java 后端代码检查规则，共63条",
      "categories": [
        "应用开发架构使用",
        "代码结构",
        "异常处理",
        "安全性",
        "其他",
        "日志输出",
        "接口定义",
        "数据库",
        "配置_工具",
        "海关定制"
      ]
    },
    "frontend": {
      "enabled": true,
      "file_patterns": [
        "**/*.js",
        "**/*.jsx",
        "**/*.ts",
        "**/*.tsx",
        "**/*.vue"
      ],
      "severity_threshold": "warning",
      "disabled_rules": [],
      "description": "前端代码检查规则（Vue/TypeScript），共105条",
      "categories": [
        "应用开发架构使用",
        "代码结构",
        "异常处理",
        "其他",
        "布局规范",
        "字体设置",
        "字体大小-标准版",
        "字体大小-关怀版",
        "颜色-海关蓝",
        "颜色-政务红",
        "边距",
        "按钮",
        "业界通用"
      ]
    }
  },

  "global_settings": {
    "max_workers": 5,
    "chunk_size": 4000,
    "chunk_overlap": 200,
    "ignored_patterns": [
      "__pycache__",
      "*.pyc",
      "node_modules",
      "dist",
      "build",
      ".git",
      ".venv",
      "venv",
      "*.min.js",
      "*.min.css"
    ],
    "report_directory": "codecheck",
    "enable_progress_tracking": true,
    "enable_resume": true
  },

  "severity_levels": {
    "error": {
      "priority": 1,
      "description": "必须修复的严重问题，可能导致系统崩溃、安全漏洞或数据丢失"
    },
    "warning": {
      "priority": 2,
      "description": "强烈建议修复的问题，影响代码质量、性能或可维护性"
    },
    "info": {
      "priority": 3,
      "description": "建议改进的问题，主要是命名规范、注释建议等"
    }
  }
}
```

#### 2.2.2 配置字段说明

##### rule_sets 配置

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| **enabled** | boolean | 是 | 是否启用该规则集 |
| **file_patterns** | array | 是 | 文件匹配模式(glob格式) |
| **severity_threshold** | string | 是 | 最低严重级别(error/warning/info) |
| **disabled_rules** | array | 否 | 禁用的规则名称列表 |
| **description** | string | 否 | 规则集描述 |
| **categories** | array | 否 | 规则分类 |

##### global_settings 配置

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| **max_workers** | integer | 5 | 并发检查的最大进程数 |
| **chunk_size** | integer | 4000 | 代码分块大小(tokens) |
| **chunk_overlap** | integer | 200 | 分块重叠大小(tokens) |
| **ignored_patterns** | array | [] | 全局忽略的文件模式 |
| **report_directory** | string | "codecheck" | 报告输出目录 |
| **enable_progress_tracking** | boolean | true | 启用进度跟踪 |
| **enable_resume** | boolean | true | 启用断点续检 |

### 2.3 规则配置最佳实践

#### 2.3.1 性能优化配置

```json
{
  "global_settings": {
    "max_workers": 8,
    "chunk_size": 3000,
    "chunk_overlap": 150,
    "ignored_patterns": [
      "__pycache__",
      "*.pyc",
      "node_modules",
      "dist",
      "build",
      ".git",
      ".venv",
      "*.test.js",
      "*.spec.js",
      "vendor",
      "third_party"
    ]
  }
}
```

**说明**:
- `max_workers=8`: 8核CPU可设置为8
- `chunk_size=3000`: 减小块大小,提高响应速度
- 忽略测试文件和第三方代码

#### 2.3.2 严格检查配置

```json
{
  "rule_sets": {
    "backend": {
      "enabled": true,
      "severity_threshold": "info",
      "disabled_rules": []
    },
    "frontend": {
      "enabled": true,
      "severity_threshold": "info",
      "disabled_rules": []
    }
  }
}
```

**说明**:
- `severity_threshold="info"`: 显示所有级别的问题
- `disabled_rules=[]`: 不禁用任何规则

#### 2.3.3 宽松检查配置

```json
{
  "rule_sets": {
    "backend": {
      "enabled": true,
      "severity_threshold": "error",
      "disabled_rules": [
        "命名规范",
        "注释完整性"
      ]
    }
  }
}
```

**说明**:
- `severity_threshold="error"`: 只显示严重错误
- 禁用命名规范等非关键规则

# 后端代码检查规则

## 分类1: 应用开发架构使用

- **严重级别**: error
- **说明**: 必须使用海关指定的开发框架...
- **检查要点**:
  - 检查是否引用了正确的框架
  - 检查框架版本是否符合要求

  ```python
  # 正确示例

...

## 分类2: 代码结构
...

### 3.3 自定义规则文件

#### 3.3.1 创建自定义规则

用户可以创建自己的规则文件,例如 `rules/custom_rules.md`:

```markdown
# 项目自定义规则

## 项目特定规范

### 规则C-1: 必须使用公司统一的日志格式
- **严重级别**: warning
- **说明**: 所有日志输出必须使用公司统一的日志格式,便于集中管理和分析
- **检查要点**:
  - 日志必须包含时间戳
  - 日志必须包含模块名
  - 日志必须包含操作用户
- **示例**:
  ```python
  # 正确示例
  logger.info(f"[{module_name}] {user} executed {action} at {timestamp}")

  # 错误示例
  print("User action")  # 不应使用print,应使用logger
  ```
```

#### 3.3.2 在配置文件中启用自定义规则

修改 `rules/rules_config.json`:

```json
{
  "rule_sets": {
    "custom": {
      "enabled": true,
      "file_patterns": ["**/*.py", "**/*.js"],
      "severity_threshold": "warning",
      "description": "项目自定义规则"
    }
  }
}
```

## 4. 文件忽略配置

### 4.1 .autocoderignore 文件

**文件名**: `.autocoderignore`

**用途**: 指定不需要处理的文件和目录,类似 `.gitignore`

**格式**: 纯文本,每行一个模式

**位置**: 项目根目录

#### 4.1.1 基本示例

```gitignore
# Python
__pycache__/
*.pyc
*.pyo
*.pyd
.Python
*.so
*.egg
*.egg-info/
dist/
build/
.venv/
venv/
env/

# JavaScript/Node
node_modules/
npm-debug.log
yarn-error.log
.npm/
.yarn/
dist/
build/

# IDE
.idea/
.vscode/
*.swp
*.swo
.DS_Store

# Git
.git/
.gitignore

# Logs
*.log
logs/

# Temporary files
*.tmp
*.temp
.cache/

# Build artifacts
target/
out/
*.class

# Test files (可选)
test/
tests/
*_test.py
*.test.js
*.spec.js

# Third-party
vendor/
third_party/
lib/

# Large media files
*.mp4
*.avi
*.mov
*.zip
*.tar.gz

# Database
*.db
*.sqlite
*.sqlite3

# Configuration with secrets (不应提交的敏感文件)
.env
secrets.yml
credentials.json
```

#### 4.1.2 模式语法

| 模式 | 说明 | 示例 |
|------|------|------|
| `*` | 匹配任意字符(不含/) | `*.pyc` 匹配所有.pyc文件 |
| `**` | 匹配任意字符(含/) | `**/test` 匹配任意层级的test目录 |
| `?` | 匹配单个字符 | `file?.txt` |
| `!` | 取反,不忽略 | `!important.log` |
| `#` | 注释 | `# This is a comment` |
| `/` | 目录 | `build/` 仅匹配build目录 |

#### 4.1.3 高级示例

```gitignore
# 忽略所有.log文件,但不忽略error.log
*.log
!error.log

# 只忽略根目录的 config.yml,不忽略子目录的
/config.yml

# 忽略所有build目录,无论嵌套多深
**/build/

# 忽略 doc 目录下除了 important.txt 的所有文件
doc/*
!doc/important.txt
```

### 4.2 .gitignore 文件

`.gitignore` 文件用于Git版本控制,格式与 `.autocoderignore` 相同,但用途不同:

- `.gitignore`: 控制Git不跟踪的文件
- `.autocoderignore`: 控制Cuscli不处理的文件

**建议**: 两个文件的内容可以保持一致或相似。

### 5.3 动作配置文件

**文件名**: `actions/*.yml`

**用途**: 定义批处理任务,用于自动化工作流

#### 5.3.1 代码生成动作示例

**文件名**: `actions/generate_service.yml`

```yaml
# 生成服务类的动作配置
action:
  name: "生成业务服务类"
  description: "根据需求自动生成业务服务类代码"

steps:
  - name: "创建服务类文件"
    type: "generate_code"
    prompt: |
      生成一个名为 {service_name} 的业务服务类:
      - 继承 BaseService
      - 包含 CRUD 方法
      - 添加日志记录
      - 添加异常处理
      - 符合海关开发规范
    output: "src/services/{service_name}.py"

  - name: "生成单元测试"
    type: "generate_code"
    prompt: |
      为 {service_name} 服务类生成单元测试
    output: "tests/services/test_{service_name}.py"

  - name: "更新__init__.py"
    type: "edit_file"
    file: "src/services/__init__.py"
    operation: "append"
    content: "from .{service_name} import {service_name}\n"

# 变量定义
variables:
  service_name:
    type: "string"
    required: true
    description: "服务类名称,如 UserService"
```

#### 5.3.2 代码重构动作示例

**文件名**: `actions/refactor_to_async.yml`

```yaml
# 将同步代码重构为异步代码
action:
  name: "重构为异步代码"
  description: "将同步函数重构为async/await模式"

steps:
  - name: "识别同步函数"
    type: "search"
    pattern: "def (.+)\\(.*\\):"
    scope: "{target_file}"

  - name: "转换为async函数"
    type: "refactor"
    prompt: |
      将以下函数转换为异步函数:
      1. 函数定义改为 async def
      2. 数据库调用改为 await
      3. 添加必要的异步支持库导入
      4. 保持原有逻辑不变
    input: "{target_file}"
    output: "{target_file}.async"

  - name: "验证语法"
    type: "run_command"
    command: "python -m py_compile {target_file}.async"

  - name: "替换原文件"
    type: "move_file"
    source: "{target_file}.async"
    target: "{target_file}"

variables:
  target_file:
    type: "string"
    required: true
    description: "要重构的文件路径"
```

#### 5.3.3 批量代码检查动作示例

**文件名**: `actions/batch_check.yml`

```yaml
# 批量代码检查
action:
  name: "批量代码质量检查"
  description: "对多个目录执行代码检查并生成汇总报告"

steps:
  - name: "检查后端代码"
    type: "code_check"
    directory: "src/backend"
    rules: "rules/backend_rules.md"
    output: "reports/backend_check.md"

  - name: "检查前端代码"
    type: "code_check"
    directory: "src/frontend"
    rules: "rules/frontend_rules.md"
    output: "reports/frontend_check.md"

  - name: "生成汇总报告"
    type: "generate_report"
    inputs:

## 9. 最佳实践

### 9.1 配置文件管理

#### 9.1.1 版本控制

**应提交到Git**:
- ✅ `rules/rules_config.json`
- ✅ `rules/*.md`
- ✅ `.autocoderignore`
- ✅ `.auto-coder/project.yml`
- ✅ `actions/*.yml`
- ✅ `.env.example`

**不应提交到Git**:
- ❌ `.env` (包含API密钥)
- ❌ `.auto-coder/llm_config.yml` (如包含密钥)
- ❌ `.auto-coder/logs/`
- ❌ `.auto-coder/indexes/`
- ❌ `codecheck/` (检查报告)

#### 9.1.2 团队协作

1. **统一规则**: 团队成员共享相同的规则文件
2. **环境变量**: 使用`.env.example`提供模板,每人配置自己的`.env`
3. **配置分层**:
   - 团队通用配置: `.auto-coder/project.yml` (提交)
   - 个人配置: `.auto-coder/local.yml` (不提交,覆盖通用配置)

#### 9.1.3 配置继承示例

```yaml
# .auto-coder/project.yml (团队通用配置)
project:
  name: "团队项目"

code_generation:
  language: "python"
  framework: "ecim"

# .auto-coder/local.yml (个人配置,覆盖通用配置)
include_file: "project.yml"

code_generation:
  model: "gpt-3.5-turbo"  # 个人可能使用不同的模型
  temperature: 0.8         # 个人偏好

logging:
  level: "DEBUG"           # 个人调试时使用DEBUG级别
```

### 9.2 安全最佳实践

1. **API密钥管理**:
   - ❌ 不要将API密钥硬编码在配置文件中
   - ✅ 使用环境变量或密钥管理服务
   - ✅ 使用 `.env` 文件并添加到 `.gitignore`

2. **敏感信息过滤**:
   - ✅ 在 `.autocoderignore` 中排除包含敏感信息的文件
   - ✅ 使用日志脱敏功能

3. **权限控制**:
   - ✅ 配置文件权限设置为 `600` 或 `640`
   - ✅ 环境变量文件权限设置为 `600`

```bash
# 设置配置文件权限
chmod 600 .env
chmod 640 .auto-coder/llm_config.yml
```

## 10. 常见问题

### 10.1 配置文件不生效

**问题**: 修改了配置文件,但系统行为没有变化

**解决方案**:
1. 检查配置文件路径是否正确
2. 检查YAML语法是否正确(使用在线YAML验证器)
3. 重启chat-auto-coder
4. 检查日志文件: `.auto-coder/logs/auto-coder.log`

### 10.2 环境变量未生效

**问题**: 在YAML中使用 `ENV {{VAR_NAME}}` 但未读取到值

**解决方案**:
1. 确认环境变量已设置: `echo $VAR_NAME`
2. 如使用 `.env` 文件,确保在启动前加载:
   ```bash
   export $(cat .env | xargs)
   chat-auto-coder
   ```
3. 或使用 `python-dotenv` 自动加载

### 10.3 规则文件解析错误

**问题**: 代码检查时提示规则文件解析失败

**解决方案**:
1. 检查Markdown格式是否正确
2. 确保三级标题格式为: `### 规则X-Y: 规则名称`
3. 确保包含必需字段: 严重级别、说明、检查要点
4. 查看详细错误信息: `auto-coder check --debug`
