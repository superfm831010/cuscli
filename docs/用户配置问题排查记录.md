# 用户配置问题排查记录

## 2025-11-10 /chat 命令调用错误模型问题

### 问题描述
用户反馈使用 `/chat` 命令时，配置的模型没有被调用，反而调用了 deepseek/v3 模型，导致 API 错误：


但普通 agentic 对话模式（直接输入文本）可以正常工作。

### 排查过程

#### 1. 初步分析
调研发现两种模式的模型选择逻辑不同：
- **普通 agentic 对话**：使用 `code_model` 配置
- **/chat 命令**：使用 `chat_model` 配置，如果没有则 fallback 到 `model`

#### 2. 代码修复
修改了 `autocoder/agent/entry_command_agent/chat.py` 的模型选择逻辑，添加 `code_model` 的 fallback：


#### 3. 问题仍未解决
修改代码后，用户重新启动 cuscli，但问题依然存在。进一步调研发现：

**用户发现关键问题**：
按照之前的二次开发记录（commit 6920aec），安装完 cuscli 后应该没有任何模型配置，需要引导用户配置。但现在却有一堆内置模型（包括 deepseek/v3）。

#### 4. 深入调研：历史遗留配置

**调研结果**：
1. **代码设计是正确的**：
   - `DEFAULT_MODELS = []` 确实为空
   - 引导设置流程（`guided_setup.py`）完整且正常
   - 新安装会创建空的 `models.json`

2. **"内置模型"实际上是历史遗留文件**：
   - 文件路径：`~/.auto-coder/keys/models.json`
   - 创建时间：2025-02-07（远早于二次开发开始时间）
   - 最后修改：2025-05-26
   - 来源：原版 auto-coder 的历史配置

3. **根本原因**：
   - 用户环境中有从原版 auto-coder 遗留下来的配置文件
   - 当模型配置不存在时，系统回退到 models.json 中的第一个模型
   - models.json 中第一个模型是 `deepseek/v3`，导致 /chat 命令调用了错误的模型

### 解决方案

**选择的方案**：清除旧配置，重新设置

**执行步骤**：
1. ✅ 备份整个 keys 目录到 `~/.auto-coder/keys.backup_20251110_145442`
2. ✅ 备份 `models.json` 到 `~/.auto-coder/keys/models.json.backup`
3. ✅ 删除 `~/.auto-coder/keys/models.json`
4. ✅ 验证清除结果

**验证结果**：
- ✅ models.json 已成功删除
- ✅ 备份文件完整保存
- ✅ 其他 API key 文件保持不变

### 预期效果

下次启动 cuscli 时：
1. 系统检测到 `models.json` 不存在
2. 自动触发引导配置流程（`guided_setup.py`）
3. 用户可以配置正确的模型
4. `/chat` 命令将使用用户配置的模型

### 经验总结

1. **设计验证**：
   - cuscli 的设计是正确的，没有内置任何模型
   - 引导设置流程完整且有效

2. **升级注意事项**：
   - 从原版 auto-coder 升级到 cuscli 时，旧配置文件会保留
   - 如果需要全新配置，应删除 `~/.auto-coder/keys/models.json`

3. **文档建议**：
   - 在安装文档中说明旧配置文件的处理方式
   - 建议首次使用时检查配置文件来源

4. **增强建议**（可选）：
   - 可以在 `initialize_system()` 中增加判断
   - 检测配置文件是否来自旧版本
   - 提示用户是否保留旧配置或重新配置
