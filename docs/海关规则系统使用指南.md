## 系统概述

### 什么是规则系统

海关规则系统是基于auto-coder的.autocoderrules机制实现的开发规范指引系统。它包含162条来自海关总署的开发规范，覆盖后端、前端和数据库设计等多个维度。

### 规则来源

所有规则条款都来自caps目录下的官方文档：

1. **backend_rules修订版.xlsx** - 52条后端规则
2. **frontend_rules修订版.xlsx** - 110条前端规则
3. **海关集中式事务型数据库设计规范.docx** - 完整数据库规范

### 规则结构

```
.autocoderrules/
├── index.md              # 规则索引（总览）
├── backend/              # 7个后端规则文件
│   ├── customs-specific.md
│   ├── architecture.md
│   ├── security.md
│   ├── exception.md
│   ├── logging.md
│   ├── api.md
│   └── database.md
└── frontend/             # 4个前端规则文件
    ├── architecture.md
    ├── ui-standards.md
    ├── layout.md
    └── component.md
```

## 使用方法

### 1. Vibecoding使用

在使用auto-coder进行代码生成时，规则会自动生效：

#### 后端开发示例

当你请求auto-coder生成Java后端代码时：

```bash
# 在chat模式下
auto-coder chat

> 帮我创建一个用户管理的Service类
```

**AI会自动遵循以下规范**：
- ✅ 使用@Service注解
- ✅ 使用@RequiredArgsConstructor构造器注入
- ✅ Service只包含业务逻辑，不直接操作数据库
- ✅ 使用统一的BizException异常封装
- ✅ 方法名遵循驼峰命名
- ✅ 方法行数不超过30行
- ✅ 避免魔数，使用常量

#### 前端开发示例

当你请求auto-coder生成Vue组件时：

```bash
> 帮我创建一个用户列表页面
```

**AI会自动遵循以下规范**：
- ✅ 使用Vue3 + TypeScript + ElementPlus
- ✅ 主色使用#0f7edf（海关蓝）
- ✅ 按钮间距12px
- ✅ 模块间距16px
- ✅ 正文字体13px（标准版）
- ✅ 查询区有圆角边框
- ✅ 统一错误处理，使用封装的request

#### 数据库设计示例

当你请求auto-coder生成数据表设计时：

```bash
> 帮我设计一个用户信息表
```

**AI会自动遵循以下规范**：
- ✅ 表名包含应用简称（如MYAPP_USER_INFO）
- ✅ 必备字段：REC_VERSION、REC_CREATE_TIME、REC_LAST_UPDATE_TIME
- ✅ 主键有业务含义（如USER_ID）
- ✅ 字段名全大写，下划线分隔
- ✅ 字符集UTF-8
- ✅ 日期字段使用DATE后缀，时间字段使用TIME后缀

### 2. 查看规则详情

查看某个规则文件的详细内容：

```bash
cat .autocoderrules/backend/security.md
```

### 3. 查看规则索引

查看所有规则概览：

```bash
cat .autocoderrules/index.md
```

### 4. 检查规则加载

确认规则文件被正确加载：

```bash
# 查看规则目录
ls -la .autocoderrules/
ls -la .autocoderrules/backend/
ls -la .autocoderrules/frontend/
```

## 规则更新维护

### 更新流程

当海关开发规范文档更新时：

1. **更新源文档**：
   ```bash
   # 将新版Excel/Word文档放入caps目录
   cp new_backend_rules.xlsx /projects/cuscli/caps/backend_rules修订版.xlsx
   ```

2. **重新提取规则**：
   ```bash
   # 使用Python重新读取并提取规则
   python3 -c "
   import pandas as pd
   df = pd.read_excel('/projects/cuscli/caps/backend_rules修订版.xlsx')
   # 分析变更...
   "
   ```

3. **更新规则文件**：
   - 编辑对应的.md文件
   - 添加新规则条款
   - 更新来源标注

4. **更新索引**：
   - 编辑 index.md
   - 更新规则数量和版本信息

5. **测试验证**：
   - 使用vibecoding测试规则效果
   - 确认新规则正确应用

### 维护注意事项

#### 1. 保持来源可追溯

每条规则必须标注来源：

```markdown
- **backend_001**: 项目父依赖应为cacp-spring-boot-parent
- 来源：backend_rules修订版.xlsx 第2行
```

#### 2. 不添加代码示例

规则文件只包含规则条款，不添加自己编写的代码示例，避免幻觉：

```markdown
<!-- ✅ 正确 -->
### 1. 禁止使用Date类
- **backend_014**: 代码中禁止使用Date类，应使用LocalDateTime替换
- 说明：java.util.Date是线程不安全的，且API设计不佳，应使用Java 8的时间API

<!-- ❌ 错误 - 不要添加代码示例 -->
### 1. 禁止使用Date类
```java
// 错误示例
Date now = new Date();

// 正确示例
LocalDateTime now = LocalDateTime.now();
```
```

#### 3. description字段要清晰

YAML元数据中的description要让LLM能准确理解：

```yaml
---
# ✅ 清晰
description: "后端安全规范，包括XSS防护、空指针防护、敏感信息保护、缓存安全等"

# ❌ 模糊
description: "安全相关规范"
---
```

#### 4. alwaysApply设置原则

- **安全规范**: 必须 true
- **架构规范**: 必须 true
- **海关特定**: 必须 true
- **编码规范**: 核心规范 true，细节规范 false
- **接口/数据库**: 根据通用性，多数 false
- **前端UI**: 色系和字体 true，组件细节 false

## 常见问题

### Q1: 规则文件放在哪里？

**A**: 规则文件应放在以下位置之一（按优先级）：

1. `.autocoderrules/` （项目根目录，优先级最高）
2. `.auto-coder/.autocoderrules/`
3. `.auto-coder/autocoderrules/`
4. `~/.auto-coder/autocoderrules/` （全局）

推荐使用项目级 `.autocoderrules/` 目录。

### Q2: alwaysApply是什么意思？

**A**:
- `alwaysApply: true` - 规则总是应用，无需LLM判断，适用于核心规范
- `alwaysApply: false` - 规则按需应用，LLM根据上下文判断是否使用

### Q3: globs字段有什么用？

**A**: globs字段指定规则适用的文件类型：

```yaml
globs:
  - "**/*.java"     # 所有Java文件
  - "**/*.py"       # 所有Python文件
  - "**/controller/**"  # controller目录下的文件
```

### Q4: 如何知道规则是否生效？

**A**:
1. 使用vibecoding生成代码，观察是否符合规范
2. 检查生成的代码是否包含：
   - 后端：CACP依赖、统一异常处理、命名规范等
   - 前端：海关蓝色系、字体大小规范、边距规范等

### Q5: 可以修改规则吗？

**A**:
- ✅ 可以修改规则的description、globs、alwaysApply
- ✅ 可以调整规则分类和文件组织
- ⚠️ 不建议修改规则条款内容（应与caps文档保持一致）
- ❌ 不要添加自己编写的代码示例

### Q6: Index.md有什么特殊之处？

**A**: Index.md总是会被加载，无论alwaysApply设置如何。它用作规则目录索引，帮助LLM了解可用的规则。

### Q7: 如何处理规则冲突？

**A**:
1. 同一文件中的规则不应冲突
2. 不同文件的规则按优先级应用
3. alwaysApply: true的规则优先级更高
4. 如有冲突，应在index.md中说明优先级

### Q8: 前端的标准版和关怀版字体如何选择？

**A**:
- **标准版**（默认）：正文13px，弹出框标题15px
- **关怀版**（无障碍模式）：正文15px，弹出框标题17px

根据项目需求在代码中实现切换机制。

### Q9: 海关蓝和政务红如何选择？

**A**:
- **海关蓝**（默认）：主色#0f7edf
- **政务红**：主题色#e6261a

根据项目定位选择主题色系，所有UI组件应统一使用同一色系。

### Q10: 规则更新后需要重启吗？

**A**:
- 规则文件修改后，下次启动auto-coder时会自动加载新规则
- 不需要重新安装或重启系统
- 建议修改后测试一次vibecoding确认效果
